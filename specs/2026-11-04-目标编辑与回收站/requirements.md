# 目标编辑与回收站 —— 需求

## 1. 背景与问题

现在「目标」只有创建和列表：

- 写错标题、判据、期限后只能重新建一个；
- 目标完成后无法标记「已完成」，只能一直堆在列表里；
- 不想要的目标无法删除，`10-目标` 与 `20-学习项目/<id> <title>/` 会一直留下；
- 没有归档概念，长列表里新旧目标混在一起。

目标下面的知识节点、学习路径、验收题、评估记录、复盘都在
`20-学习项目/<id> <title>/` 分区里；资源在 `40-资源/`，可能被多个目标共享。
所以「删除目标」必须是一次**有清单、可恢复**的迁移，而不是删一个 Markdown 文件。

## 2. 目标

1. 目标支持编辑：标题、成功判据、类型/期限、状态；
2. 标题改名时，目标文件与学习项目分区目录同步改名，id 不变；
3. 状态支持：**在用 / 暂停 / 已完成 / 已归档**；归档只隐藏，不移动文件；
4. 删除是**软删除到 `99-回收站`**，可以恢复，也可以彻底删除；
5. 删除时目标文件、分区（节点/路径/验收/复盘）与**独占资源**一起进回收站；
   共享资源只解除该目标的节点关联，文件保留；
6. 目标页底部提供回收站列表、恢复、彻底删除；
7. 所有修改记录 `updated_at`。

## 3. 非目标

- 不做多版本历史 / 逐次操作日志（只记 `updated_at`）；
- 不做批量编辑 / 批量删除；
- 不做权限、多人协作、云端同步；
- 不强制「已完成」前必须通过验收或写复盘（只提示）；
- 不改变「Markdown 是唯一真相」的存储原则；
- 不做回收站自动过期清理（先手动彻底删除）。

## 4. 数据模型

### 4.1 目标 frontmatter

```yaml
status: 在用 # 在用 / 暂停 / 已完成 / 已归档
kind: 常规 # 激励性 / 常规
success_criteria: '……'
deadline: 2026-12-31
updated_at: '2026-11-04T…'
```

- `updated_at` 新建时写入，之后每次 PATCH 更新；
- 旧目标没有 `updated_at` 时读取为 `created_at`（或空），不报错；
- `status` 缺省仍为「在用」，兼容旧文件。

### 4.2 状态语义

| 状态   | 列表                 | 文件 | 说明                           |
| ------ | -------------------- | ---- | ------------------------------ |
| 在用   | 显示                 | 原地 | 默认                           |
| 暂停   | 显示                 | 原地 | 暂不推进                       |
| 已完成 | 显示                 | 原地 | 正常结果；不强制验收/复盘      |
| 已归档 | 默认隐藏，可筛选显示 | 原地 | 不移动、不删除，可改回其他状态 |

### 4.3 回收站

```
99-回收站/
  <YYYYMMDD-HHmmss>-<goalId>/
    manifest.json
    goal.md                 # 原 10-目标/<id> <title>.md
    partition/              # 原 20-学习项目/<id> <title>/
    resources/
      <原相对路径>          # 独占资源文件，保留目录结构
```

`manifest.json`：

```json
{
  "version": 1,
  "goalId": "abc123",
  "title": "原目标标题",
  "deletedAt": "2026-11-04T…",
  "goalFile": "10-目标/abc123 原标题.md",
  "partitionDir": "20-学习项目/abc123 原标题",
  "exclusiveResources": ["40-资源/r1 资源.md"],
  "sharedResources": [{ "resourceId": "r2", "nodeIds": ["n1"] }]
}
```

- 目录名即回收站条目 id（URL 中编码）；
- 独占资源：资源的所有 `nodeIds` 都属于该目标的节点；
- 共享资源：至少一个 `nodeIds` 属于其他目标，删除时只 `detach` 本目标的节点；
- 恢复时把 `sharedResources` 的节点关联重新挂上。

## 5. 功能需求

### FR-1 编辑目标

- 目标卡片「⋯」→「编辑」打开弹窗；
- 可改：标题、成功判据、类型（激励性/常规）、期限、状态；
- 至少改一个字段；空提交返回 400；
- 保存后列表立即刷新，目标文件 `updated_at` 更新；
- 校验：
  - 标题 1–200 字；
  - 成功判据 ≤500 字，清空则删除字段；
  - 激励性必须有期限；把常规改成激励性但没期限 → 400；
  - 期限必须是 `YYYY-MM-DD`；清空期限仅允许常规；
  - 状态只能是四个枚举值。

### FR-2 改名

- 标题变化时：
  - `10-目标/<id> <旧标题>.md` → `10-目标/<id> <新标题>.md`；
  - `20-学习项目/<id> <旧标题>/` → `20-学习项目/<id> <新标题>/`；
  - id、frontmatter 里的 id、所有节点/路径/资源关联都不变；
- 先改目标文件，再改分区目录；任一步失败要回滚已完成的移动；
- 目标标题导致路径冲突时返回 409，不做覆盖；
- 改名后强制重建目标索引。

### FR-3 状态

- 卡片菜单可直接切换状态，或编辑弹窗里改；
- 「已完成」不强制验收/复盘；若该目标没有验收记录或复盘，弹窗里提示一句，但允许保存；
- 「已归档」只在目标列表默认隐藏；提供「显示已归档」开关；
- 归档不移动文件，改回其他状态即恢复显示。

### FR-4 软删除

- 卡片「⋯」→「删除」→ 普通二次确认弹窗（展示将一起删除的内容数量）；
- 确认后：
  1. 计算目标下的节点与资源归属；
  2. 独占资源移动到回收站 `resources/`；
  3. 共享资源逐个 `detach` 本目标的节点，文件保留；
  4. 目标分区目录移动到回收站 `partition/`；
  5. 目标文件移动到回收站 `goal.md`；
  6. 写 `manifest.json`；
  7. 重建目标索引；
- 任意步骤失败时，尽量回滚已移动的文件并返回错误；
- 删除成功后列表不再显示该目标。

### FR-5 回收站

- 目标页底部「回收站」折叠区，默认收起；
- 列表显示：原目标标题、删除时间、节点/路径/资源数量；
- 「恢复」：
  - 目标 id 已存在 → 409，提示先处理同名目标；
  - 恢复目标文件与分区目录（若原路径被占用则 409）；
  - 独占资源移回原路径；
  - 共享资源的节点关联重新挂上；
  - 删除 manifest 与空目录，重建索引；
- 「彻底删除」：
  - 二次确认；
  - 删除整个回收站条目目录（含独占资源）；
  - 不可恢复；
- 空回收站显示「暂无已删除目标」。

### FR-6 列表与筛选

- 默认列表：在用 / 暂停 / 已完成，按现有排序；
- 「显示已归档」开关：打开后加入已归档；
- 卡片显示状态徽标、期限、最近更新（有 `updated_at` 时）；
- 删除后的目标不进入列表索引。

### FR-7 API

- `PATCH /api/goals/:id`：编辑（部分字段）；
- `DELETE /api/goals/:id`：软删除，返回 `{ trashId }`；
- `GET /api/trash`：回收站列表；
- `POST /api/trash/:trashId/restore`：恢复；
- `DELETE /api/trash/:trashId`：彻底删除；
- `GET /api/goals?includeArchived=1`：包含已归档；
- 错误码：400 参数、404 不存在、409 路径/id 冲突、500 文件系统失败。

### FR-8 安全与一致性

- 所有移动限制在库根内，拒绝 `..`/绝对路径；
- 软删除/恢复/彻底删除全程使用同一 manifest，避免半删状态；
- 操作完成后重建目标索引，避免 `GET /api/goals` 读到旧缓存；
- 文件系统失败要回滚并保留原状，不能出现「目标文件没了、分区还在」。

## 6. UI 结构

- 目标卡片右上角「⋯」菜单：编辑 / 状态（子菜单）/ 删除；
- 编辑弹窗：标题、类型、期限、成功判据、状态；保存/取消；
- 删除确认弹窗：列出「将移动 N 个节点、M 条路径、K 条资源到回收站」；
- 目标页底部回收站折叠区：每条「标题 · 删除时间 · 恢复 / 彻底删除」；
- 状态徽标：在用（默认）、暂停（黄）、已完成（绿）、已归档（灰）。

## 7. 验收标准

1. 改标题后，目标文件名与分区目录名同步变化，id 与关联不变；
2. 改判据/期限/类型/状态后刷新页面仍生效，`updated_at` 变化；
3. 激励性无期限被 400 拒绝；
4. 删除目标后列表消失，回收站出现条目；
5. 回收站恢复后目标、分区、独占资源、共享关联全部回来；
6. 恢复时 id 冲突返回 409；
7. 彻底删除后目录与独占资源不可恢复；
8. 共享资源在删除后仍存在于资源库，且其他目标的节点关联还在；
9. 归档目标默认隐藏，打开开关可见，改回在用后恢复显示；
10. 全量测试、lint、typecheck 通过。

## 8. 风险

- **跨目录移动不是事务**：用「记录已移动项 + 逆序回滚」降低半删风险；
- **共享资源归属判断**依赖节点 id；节点缺失时按「无归属」保留，不贸然删除；
- **改名冲突**（标题相近）用 409 拒绝，不自动加后缀；
- **索引缓存**：删除/恢复/改名后必须强制重建，否则列表仍显示旧目标；
- **用户误删**：软删除 + 二次确认兜底，但彻底删除不可恢复。
