# 目标编辑与回收站 —— 验证计划

## 1. 验证目标

1. 目标字段可以改，校验正确，`updated_at` 会更新；
2. 改名时目标文件与分区目录同步变化，id 与所有关联不变；
3. 状态四态可用，已归档默认隐藏、可恢复显示；
4. 删除是软删除：目标、分区、独占资源进回收站，共享资源只解除关联；
5. 回收站可以恢复、可以彻底删除，冲突有明确提示；
6. 全部操作不破坏现有 507 条测试与库结构。

## 2. 测试分层

| 层   | 内容                         | 命令                                                              |
| ---- | ---------------------------- | ----------------------------------------------------------------- |
| 领域 | 更新、改名、回收站、回滚     | `npx vitest run tests/goal-edit.test.ts tests/goal-trash.test.ts` |

## 3. 领域测试清单

### 3.1 编辑（`tests/goal-edit.test.ts`）

- 改标题：frontmatter `title`、文件名、分区目录同时变化；
- 只改成功判据：文件不动、内容变化、`updated_at` 变化；
- 清空成功判据：字段被删除；
- 常规 → 激励性但无期限：`INVALID_INPUT`；
- 激励性期限改空：`INVALID_INPUT`；
- 状态改成四个合法值；非法值 400；
- 旧目标没有 `updated_at`：读取为 `createdAt`，修改后写入；
- 空 patch：400；
- 改名冲突：409 / `INVALID_INPUT`，原文件不被覆盖；
- 分区目录重命名失败（mock）：目标文件回滚。

### 3.2 回收站（`tests/goal-trash.test.ts`）

用临时库构造：

- 目标 + 2 节点 + 1 阶段 + 1 题 + 1 评估 + 1 复盘；
- 资源 A 只挂目标节点（独占）；
- 资源 B 同时挂另一个目标的节点（共享）。

断言：

1. `trashGoal` 后：
   - `10-目标` 下目标文件消失；
   - `20-学习项目/<id> ...` 消失；
   - `99-回收站/<条目>/goal.md`、`partition/`、`resources/` 存在；
   - A 文件被移动，B 文件仍在 `40-资源`；
   - B 的 `nodeIds` 不再含被删目标的节点，其他目标节点仍在；
   - manifest 字段完整。
2. `listTrash` 返回标题、删除时间、计数。
3. `restoreTrash` 后：
   - 目标文件/分区/资源 A 回到原位；
   - 资源 B 的关联恢复；
   - 回收站条目消失。
4. 恢复时 id 已存在 → 409；
5. 恢复时目标路径被占用 → 409，文件不丢；
6. `purgeTrash` 后条目目录、goal.md、partition、独占资源全部删除；
7. 共享资源在彻底删除后仍保留；
8. 删除过程中第二步抛错 → 已移动项回滚，目标仍可用；
9. manifest 损坏/缺失 → 返回错误，不误删其他目录。

## 4. API 测试清单

`tests/api-goals-trash.test.ts`：

1. `PATCH /api/goals/:id` 200，返回更新后的目标；
2. 空 body → 400；
3. 激励性无期限 → 400；
4. `DELETE /api/goals/:id` 200，返回 `{ trashId }`；
5. 删除后 `GET /api/goals` 不含该目标，`GET /api/trash` 含条目；
6. `POST /api/trash/:id/restore` 200，目标回到列表；
7. 重复恢复 → 404；
8. `DELETE /api/trash/:id` 204，再查 404；
9. `GET /api/goals?includeArchived=1` 含已归档，缺省不含；
10. 非法 trashId（含 `..`）→ 400/404，不越界。

## 5. 手工验收场景

### S1 编辑与改名

1. 目标「一天学会定语从句」→ 编辑，改标题为「两天吃透定语从句」；
2. 保存；
3. 检查 `10-目标` 文件名、`20-学习项目` 目录名都变化；
4. 打开地图/路径/资源，节点与资源关联仍在；
5. 刷新列表，新标题显示。

### S2 状态与归档

1. 改成「暂停」→ 列表显示暂停徽标；
2. 改成「已完成」→ 显示完成徽标，不强制验收；
3. 改成「已归档」→ 默认列表消失；
4. 打开「显示已归档」→ 出现；
5. 改回「在用」→ 默认列表恢复。

### S3 删除与级联

1. 目标下已有节点、路径、验收、复盘、独占资源；
2. 「⋯」→ 删除 → 二次确认显示数量；
3. 确认后列表消失；
4. `99-回收站` 出现条目，goal.md / partition / resources 齐全；
5. 共享资源文件仍在 `40-资源`，关联只剩其他目标。

### S4 恢复

1. 回收站点恢复；
2. 目标、分区、独占资源回到原位；
3. 共享资源关联恢复；
4. 地图/路径/资源页面数据完整；
5. 回收站条目消失。

### S5 冲突

1. 删除目标后重新建一个同 id（或手工构造）目标；
2. 恢复 → 409，提示先处理同名目标；
3. 原回收站文件不被破坏。

### S6 彻底删除

1. 回收站点彻底删除 → 二次确认；
2. 条目目录消失；
3. 独占资源不可恢复；
4. 共享资源仍存在。

### S7 失败回滚

1. 用只读/占用文件模拟移动失败；
2. 删除返回错误；
3. 目标文件、分区、资源仍在原位，库可继续使用。

## 8. 已知限制（验收时接受）

- 文件名改名不是跨磁盘事务，极端断电可能留下半移动；用 manifest 与回滚降低风险；
- 不做版本历史，只保留 `updated_at`；
- 不做回收站自动过期；
- 不做批量操作。
