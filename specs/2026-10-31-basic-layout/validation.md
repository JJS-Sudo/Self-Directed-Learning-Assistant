## 2. 验收场景

### V1 · 六区可达（dev）

```bash
npm run dev     # 浏览器 3000
```

逐个打开 `/`、`/map`、`/path`、`/resources`、`/assess`、`/retro`：

| 观察项 | 期望                                              |
| ------ | ------------------------------------------------- |
| 标题   | 与该区导航一致                                    |
| 导航   | 当前项高亮且 `aria-current="page"`                |
| 内容   | 定位句 + 「会出现什么」；目标区额外有 health 三项 |
| 主行动 | 未开放的按钮 `disabled`，旁边标「阶段 N 开放」    |

### V2 · 刷新与深链

在 `/map` 按 F5、再直接粘贴 `/retro` 到地址栏、再对 `/resources` 刷新：

- 三次都停在同一区，不 404、不白屏；
- 开发（Vite）与生产（`npm start`）各验一遍。

### V3 · 404

访问 `/nope` 与 `/goals/xyz/map`：

- 页面显示「没有这个区」+ 回到目标的链接；
- `curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/nope` → `200`（前端兜底，服务端不区分）；
- API 例外：`/api/nope` 仍是 JSON 404（阶段 1 的行为不能退化）。

### V4 · 生产模式的两个入口

```bash
npm run build && npm start
```

- `/` 与 `/resources` 都返回 SPA（地址栏刷新不跳旧页）；
- 把 `dist/web` 改名后重启：`/` 与 `/resources` 回到旧服务端页面，`/healthz` 正常 —— 证明「无构建时降级」没有被破坏。

### V5 · 375px 视口

DevTools 设备模式设 375×812：

- 导航在一行内横向滚动，不换行、不遮挡标题；
- 页面无横向滚动条（`document.documentElement.scrollWidth <= innerWidth`）；
- 六个区各截一张（至少目标与资源两区）。

### V6 · 键盘走查

只用键盘：

- Tab 依次经过六个导航项，焦点环可见；
- Enter 进入目标区，`aria-current` 落在当前项；
- 404 页的「回到目标」可 Tab 到并回车生效。

### V7 · 没有假数据

- 六区页面里不存在「示例目标」「示例节点」这类占位数据；
- 目标区的 health 三项来自 `/api/health` 的真实响应（删库后应显示未就绪）。

## 4. 不通过的样子

- 为了「看起来有内容」往空状态里塞示例数据。
- 五个禁用按钮却没有任何「阶段 N 开放」说明，用户以为坏了。
- 生产模式 `/resources` 仍返回旧 SSR 页面（导航「漏一区」）。
- 删掉 `dist/web` 后 `/` 直接 404（把降级路径做坏了）。
- 导航在 375px 下换行成两排或产生横向滚动条。
- 把 `home-page.test.ts` / `resources-page.test.ts` 删掉或改断言来「通过」。
- 引入第三方字体、图标库 CDN 或分析脚本。

## 6. 评审者 5 分钟检查单

1. 拉分支 → `npm ci` → `npm run dev`，直接粘 `/retro` 到地址栏：进得去吗？刷新还在吗？
2. 点六个导航项，看是否有哪一区其实跳回了旧服务端页面。
3. 随手输一个 `/nope`：是 404 页还是白屏/报错页？
4. 设备模式切 375px：导航换行了吗？有没有横向滚动条？
5. `npm run build && npm start`，再对 `/resources` 刷新一次；然后临时改名 `dist/web` 重启，确认旧页面回来了。
