## 2. 验收场景

### V1 · 从节点到路径（临时库）

```bash
$env:SDL_VAULT_PATH = "$env:TEMP\sdl-path-smoke"
npm run dev
```

1. 路径页选目标（先在地图页生成过节点）；
2. 点「估算」→ 显示 token 估算；
3. 点「生成路径」→ 出现 2–5 段，每段带节点、估时、checks、封闭题与开放题；
4. 改一段的 checks、删掉一段、改一道题干；
5. 点「确认落盘」→ 页面出现路径与题目。

### V2 · 覆盖 100%

```bash
npm run maps
```

- 输出里**没有**「没有被任何路径段覆盖的叶子节点」；
- 路径页顶部警告区为空。

### V3 · 只追加，不覆盖旧段

先手工建一段（或先落盘一次），再生成并落盘一次：

- 旧段的 id 与内容不变；
- 新段 `order` 从旧最大值 +1 开始；
- 总段数 = 旧 + 新。

### V4 · 覆盖不足时的补段

单测覆盖：

- 第一块返回的段只盖了 3/4 个叶子 → 触发第二次调用（带「还差哪个节点」）；
- 第二次补齐 → 候选覆盖完整；
- 两次仍缺 → 返回警告「以下叶子仍未被路径覆盖：…」。

### V5 · checks 的可判定性

| 输入                         | 期望                                              |
| ---------------------------- | ------------------------------------------------- |
| `checks: []`                 | 400，明确说「至少一条」                           |
| `checks: ['能讲清']`（5 字） | 400，说「太短，写不清判据」                       |
| `checks: ['了解线性回归']`   | **允许落盘**，但返回/显示警告「这条判据不可判定」 |

### V6 · 未配置 key

```bash
curl -s -o - -w "\n%{http_code}\n" -X POST localhost:3000/api/goals/<id>/path/preview
```

- 503 `LLM_NOT_CONFIGURED`；
- 页面显示配置指引，不是白屏；
- 网络面板没有 `api.deepseek.com` 请求。

### V7 · 真实冒烟（需要 key）

在 `%TEMP%` 的临时库上跑 V1 + V2，记录：

- 段数 / 题数 / 耗时；
- `npm run maps` 的覆盖警告是否为 0；
- 冒烟前后真实运行库 `git status` 无变化。

## 4. 不通过的样子

- 没有 checks 的段被写进库。
- 封闭题缺少 `answer` 或解析，仍然落盘。
- 覆盖不足时静默成功（没有警告、也没有补段）。
- 补段逻辑无限重试或调用次数不封顶。
- 落盘时覆盖旧段、或把 `order` 从 1 重排导致旧段顺序被改。
- 接受模型伪造的节点 id（不是该目标的节点）。
- 模糊 checks 被拦死（与 D9 相反）或完全没提示。
- 真实冒烟写进真实运行库。
- 为通过测试放宽既有 307 条用例。

## 6. 评审者 5 分钟检查单

1. 生成一次路径：确认前库里的段数变了吗？（不该变）
2. 确认落盘后 `npm run maps`：还有「未被路径段覆盖的叶子」吗？（不该有）
3. 手动建一段再生成：旧段还在吗？新段的 order 接在后面吗？
4. 塞一条 `checks: ['了解线性回归']`：是警告还是 400？
5. 断开 key：preview 是 503 还是空转？
6. 冒烟后：真实运行库的 `git status` 干净吗？
