## 3. 决策

| 编号 | 决策                                                                                  | 理由                                                 | 影响                                           |
| ---- | ------------------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| D1   | 路径 + 题目 + 页面一次做全                                                            | 没有题的路径无法验收，闭环缺一环                     | PR 较大                                        |
| D2   | **每段两道题：封闭 + 开放**（访谈选择，比 roadmap 的「1 道封闭」多一道）              | 封闭题能自动判对错，开放题强制费曼复述；两种判据互补 | 每段多一次生成；验收记录阶段要支持两种 `mode`  |
| D3   | 生成后**先审核再落盘**                                                                | 模型的分段与题目需要人否决，复用阶段 5 模式          | 前端多一屏编辑态                               |
| D4   | 分段由**模型按学习单位**决定，服务端只验证覆盖                                        | 服务器不该猜「一节课多长」                           | 覆盖不足时靠 D5 补                             |
| D5   | 覆盖不足 → **带缺口再生成一次**，仍不足则警告不阻止                                   | 兼顾质量与可用性                                     | 最多两次生成，费用可估                         |
| D6   | 题目**随路径一起生成**                                                                | 段与题在同一响应里，绑定关系不会被后续编辑破坏       | 一次调用返回段 + 题                            |
| D7   | 已有路径段**只追加**，`order` 重排到末尾                                              | 不删用户手写的段                                     | 重复生成会堆段，需要人工收拾                   |
| D8   | checks 校验**下沉到领域层**，所有写盘入口共用                                         | 修 SOP 第 8 节第 2 条：规则之前只写在无入口的函数里  | `createStage()` 增加明确错误；API 不用重复校验 |
| D9   | 「可判定」的确定性部分只查非空与最小长度；**模糊措辞（理解/了解/熟悉…）给警告不拦截** | 机器判断不了「是否可判定」，拦死会误伤               | UI 显示警告，落盘仍允许                        |

### 3.1 接口契约

```ts
// POST /api/goals/:id/path/preview   body: {}（用该目标已有的节点）
{
  stages: {
    tempId: string
    title: string
    estimate: string            // "约 0.5 天"
    nodeIds: string[]           // 真实节点 id
    checks: string[]
    questions: {
      tempId: string
      kind: '封闭' | '开放'
      stem: string
      answer?: string           // 封闭必填
      explanation?: string      // 封闭必填，写入正文受管区块
      nodeId?: string
    }[]
  }[]
  warnings: string[]
  usage: { promptTokens?: number; completionTokens?: number }
}

// POST /api/goals/:id/path/commit   body: { stages }
{ createdStages: number; createdQuestions: number; warnings: string[] }

// GET /api/goals/:id/path
{ stages: {...}[], warnings: string[] }   // 含四类覆盖警告
```

- 未配置 key：`preview` → 503 `LLM_NOT_CONFIGURED`；commit/get 不需要 key。
- 节点 id 不属于该目标 / 不存在 → 400。
- 开放题不写 `answer`；封闭题缺 `answer` 或 `explanation` → 400（领域层报错）。

### 3.2 「可判定」的确定性口径

- 领域层强制：`checks` 至少一条、每条去空白后长度 ≥ 6，否则报错；
- 模糊措辞黑名单（`理解|了解|熟悉|掌握|知道` 开头）只产生**警告**，不阻止落盘；
- 提示词要求每条 checks 写成「能画出/能说出/能手算/能对比」这类可观察动作。

## 5. 风险

| 风险                           | 缓解                                                            |
| ------------------------------ | --------------------------------------------------------------- |
| 模型给出的 `nodeIds` 含伪造 id | 落盘前逐个 `requireNode` 并校验 goal 归属；不合法整批 400       |
| 一次生成覆盖不全               | D5 补段；仍缺则警告并列在页面                                   |
| 段与题绑定错乱                 | 题先落盘拿到 id，再写段的 `questions` 数组                      |
| 反复生成堆段                   | 只追加 + 页面显示总段数；文档写明需要手动清理                   |
| 模糊 checks 混过校验           | 黑名单警告 + 审核页可编辑                                       |
| 费用                           | preview 前显示预估（沿用阶段 5 的 estimate 思路，按节点数估算） |
