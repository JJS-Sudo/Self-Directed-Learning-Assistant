## 2. 验收场景

### V1 · 从空库到一张图（临时库）

```bash
$env:SDL_VAULT_PATH = "$env:TEMP\sdl-map-smoke"
# 复制 seeds 或手工建一个目标后启动
npm run dev
```

1. 地图页选目标 → 贴入一段真实目录（10–20 行）；
2. 点「估算」→ 显示「约 N token · ¥X（估算）」；
3. 点「生成候选」→ 出现候选列表（5–15 条）；
4. 改一条标题、删一条、把一条的父级改成顶层；
5. 点「确认落盘」→ 图出现，节点数与候选一致；
6. 刷新 → 图仍在（数据已落盘）。

### V2 · 预览不写库

```bash
curl -s localhost:3000/api/goals/<id>/map | jq '.nodes | length'
curl -s -X POST .../map/preview -d '{"material":"..."}' > /dev/null
curl -s localhost:3000/api/goals/<id>/map | jq '.nodes | length'
```

两次数字相同。同时 `10-学习项目/<目标>/知识网/` 下没有新文件。

### V3 · 覆盖警告不阻止

在没有任何路径段的库里 commit：

- 响应 `warnings` 至少含「没有被任何路径段覆盖的叶子节点」；
- 页面红字显示这条警告，**但节点确实写进了库**；
- 再跑 `npm run maps`，命令行也报同样的四类覆盖警告。

### V4 · 未配置 key

```bash
# 不带 DEEPSEEK_API_KEY 启动
curl -s -o - -w "\n%{http_code}\n" -X POST localhost:3000/api/goals/<id>/map/preview -d '{"material":"x"}'
```

- 状态 503，code `LLM_NOT_CONFIGURED`；
- 没有发往 `api.deepseek.com` 的请求；
- 页面显示配置指引，不是白屏。

### V5 · 切块与输入上限

单测覆盖：

- 100 个非空小节、每块 8 节 → 13 个请求（最后一块 4 节）；
- 输入 100001 字符 → 400 `LLM_BAD_INPUT`，假 `fetch` 调用 0 次。

### V6 · 重名与排序

同一批里出现两个「线性回归」：

- 落盘后第二个标题变成「线性回归（2）」；
- 同级 `order` 从 1 连续递增；
- 父节点的 `up` 指向真实存在的 id。

### V7 · 图交互

- 拖拽一个节点，连线跟随；
- 滚轮缩放；
- 刷新页面 → 位置回到自动布局（本期不持久化坐标，这是预期）。

### V8 · 真实冒烟（需要真 key）

在 `%TEMP%` 的临时库上跑 V1 全流程，并记录：

- 节点数与耗时；
- 是否出现结构警告；
- **冒烟前后真实运行库的节点数不变**（用 `listNodes` 或目录计数证明）。

## 4. 不通过的样子

- preview 直接把节点写进库（「先候选、后写入」被破坏）。
- 确认页不能改/删候选，用户只能整批接受。
- 覆盖检查不通过就禁止落盘（与 D7 相反）。
- 重名直接覆盖旧节点，或产生两个同名节点。
- 图只是一个列表 / 表格，或拖不动。
- 估算接口偷偷调用了模型。
- 真实冒烟写进了真实运行库。
- 用 `any` 把上下文撑到 100k 字符一次发完，再宣称「支持大目录」。
- 为通过测试放宽既有 227 条用例。

## 6. 评审者 5 分钟检查单

1. 贴一段目录，点生成：候选能改能删吗？确认前库里有没有多出文件？
2. 确认落盘后刷新：图还在吗？节点数对得上吗？
3. 删掉路径段概念（库是空的）：警告出现了吗？落盘被拦了吗？（不应被拦）
4. 断开 key：preview 是 503 还是不报错地空转？
5. 看估算接口的测试：上游调用次数是 0 吗？
6. 真实冒烟后，运行库节点数变了吗？（不该变）
