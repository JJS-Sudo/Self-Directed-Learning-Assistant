# 资源随路径自动检索 —— 需求

## 1. 背景与问题

现在的资源功能是**两套断开的流程**：

- `资源`页：手动勾选节点（最多 5 个）→ 检索 → 勾选候选 → 落盘；
- `路径`页：只展示已经落盘的 `stage.resources`，不会主动找资源。

结果是：路径有了节点，资源却要用户回到资源页再操作一遍；而且 5 个节点的上限让长路径根本补不全。
2026-11-04 还暴露出 AI 地图候选边字段未映射、落盘 400 的 bug（已修），说明「生成 → 落盘」链路的
每一段都需要有回归测试。

## 2. 目标

1. **路径落盘后自动为路径里的每个节点找资源**，不需要用户再进资源页；
2. 资源的检索结果**直接落盘**，路径页立即可见；
3. 路径页**按节点分组**展示资源链接，并给出检索进度、失败标记与重试入口；
4. 资源页改为**总览 + 手动补检**，去掉 5 个节点上限；
5. 没有 Tavily Key 时，用**平台搜索页链接**兜底（标记「未验证」），不让资源区空白；
6. 同一个 URL 可以服务多个节点；已有资源复用，只补缺失。

## 3. 非目标（本次不做）

- 不做免 Key 的网页抓取（Bing / DuckDuckGo / Google HTML 抓取）；
- 不做 SearXNG / Brave / Serper 等额外搜索源（架构预留，后续可插）；
- 不做资源的自动定时刷新、内容摘要、付费墙识别；
- 不改变知识地图生成与路径生成的模型提示词；
- 不改变「资源是 Markdown 文件、库是唯一真相」的存储原则。

## 4. 用户故事

- 作为学习者，我点「生成路径 → 确认落盘」后，希望每个阶段、每个知识点下面直接出现 1–2 个可点的资源，而不是再去资源页勾选。
- 作为没有 Tavily Key 的用户，我希望至少能点到 B 站 / YouTube / Bing 的搜索结果页，而不是看到「未配置搜索」。
- 作为用户，我希望某个节点没搜到资源时不影响其他节点，并且能单独重试。
- 作为用户，我希望同一个好资源不要因为挂在两个节点下就重复出现两份文件。
- 作为用户，我希望旧的路径也能一键补齐资源，而不是重新生成。

## 5. 功能需求

### FR-1 自动触发

- `POST /api/goals/:id/path/commit` 成功后，前端立即调用资源自动补齐接口；
- 覆盖两条路径生成入口：AI 自动生成路径、从材料生成路径；
- 旧路径不自动跑；路径页提供「补齐资源 / 重新补齐」按钮手动触发。

### FR-2 覆盖范围与上限

- 取该目标路径阶段里出现过的**所有节点 id**，按阶段顺序去重；
- 一次最多处理 **40 个节点**；超过时只处理前 40 个，并返回 `truncated` 警告；
- 节点已经不属于该目标时跳过并记警告，不中断。

### FR-3 检索与数量

- 每个节点最多 **1 次搜索**，取前 **2 条**结果；
- 同一 URL 全局只保留一份资源文件，但可以关联多个节点（见 FR-8）；
- 已存在资源的节点，`fill` 模式跳过；`refresh` 模式重新补齐缺失/未验证项。

### FR-4 直接落盘

- 自动流程不经过候选勾选，检索成功即写入 `40-资源/`；
- 写入后路径页重新加载即可看到；
- 资源的 `rank_reason` 仍按现有画像规则生成。

### FR-5 进度（SSE）

- 新接口用 Server-Sent Events 推送进度；
- 事件序列：
  - `start { total, searchConfigured }`
  - `progress { done, total, nodeId, nodeTitle, found }`
  - `warning { message }`
  - `done { created, linked, skipped, failures, truncated }`
  - `error { message }`（仅整体失败）
- 前端显示「正在为第 N/M 个节点找资源：<节点名>」与进度条；
- 客户端断开时服务端停止后续搜索（AbortSignal）。

### FR-6 失败与重试

- 单节点搜索失败/0 结果：不阻塞其他节点，记录 `failures`；
- 路径页对失败节点显示「未找到资源」；
- 提供：
  - 单节点「重试」；
  - 整条路径「重新补齐」（`refresh`）。
- 重试范围通过请求体 `nodeIds` 指定，缺省为整条路径。

### FR-7 无 Tavily 的兜底

- Tavily 未配置时，为缺失节点生成 **平台搜索页链接**（不抓取网页）：
  - 视频偏好：B 站搜索、YouTube 搜索；
  - 文字/不限偏好：Bing 搜索；
  - 代码类节点（标题含 HTML/CSS/JS/TS/React/Python 等）：MDN 搜索优先；
- 每个节点最多 2 条，标题形如「在 B 站搜索“贝叶斯定理”」；
- 资源标记 `unverified: true`，路径页显示「未验证」徽标；
- 这些资源**落盘**；配置 Tavily 后执行 `refresh`，用真实检索结果替换该节点的未验证链接。

### FR-8 同一 URL 多节点共享

- 资源文件支持 `nodes: [节点 wikilink...]`；
- 旧字段 `node` 保留为第一个节点，兼容旧版本与旧文件；
- `persistResources` 遇到已存在的 URL：
  - 若该节点未关联 → 只追加节点关联（`linked`），不新建文件；
  - 若已关联 → 跳过（`skipped`）；
- 路径页在多个节点下都能看到同一资源；
- 资源的 URL 全局唯一（同一个 URL 不重复建文件）。

### FR-9 路径页展示

- 每个阶段下按 `stage.nodeIds` 分组展示：
  - 节点标题；
  - 该节点的资源（标题、平台、价格/时长、等级、跳转链接）；
  - 没有资源时显示「未找到资源」与「重试」；
  - `unverified` 资源显示「未验证」徽标；
- 阶段顶部显示资源总数与本段节点数；
- 页面顶部提供「重新补齐资源」；没有 Tavily 时提示「未配置 Tavily，当前为搜索页链接」与配置入口。

### FR-10 资源页改造

- 去掉「最多 5 个节点」限制（前端与后端 schema 同步改）；
- 改为总览：
  - 按目标/节点分组列出全部资源；
  - 支持筛选「已验证 / 未验证」；
  - 支持删除资源（新增 `DELETE /api/resources/:id`）；
- 保留手动检索：选任意节点 → 检索候选 → 勾选 → 落盘；
- 提供「补齐缺失资源」按钮，复用自动流程与进度。

### FR-11 旧路径补齐

- 路径页对已有路径提供「补齐资源」；
- 调用同一个自动接口，默认 `fill`，跳过已有资源的节点。

### FR-12 数据兼容

- 旧资源只有 `node` 字段：读取时归一化为 `nodeIds=[node]`；
- 新写入同时写 `node`（第一个）与 `nodes`（全部）；
- 不要求迁移脚本；在下一次写该资源时自然升级；
- 旧版应用仍能读到第一个节点。

## 6. 数据模型

### 6.1 资源 frontmatter（新增字段）

```yaml
title: 贝叶斯定理可视化
node: '[[n1|贝叶斯定理]]' # 兼容字段：第一个节点
nodes:
  - '[[n1|贝叶斯定理]]'
  - '[[n2|先验与后验]]'
url: https://...
platform: B站
level: 入门
media: 视频
unverified: true # 仅平台搜索页兜底时为 true
```

### 6.2 领域对象

```ts
interface ResourceSummary {
  // 现有字段…
  nodeIds: string[]
  nodeId?: string // 兼容：nodeIds[0]
  unverified?: boolean
}
```

### 6.3 路径 DTO 扩展

```ts
interface PathStageNodeDto {
  id: string
  title: string
}
interface PathStageResourceDto {
  // 现有字段…
  nodeId?: string
  nodeTitle?: string
  unverified?: boolean
}
interface PathStageDto {
  // 现有字段…
  nodes: PathStageNodeDto[] // 供前端分组；nodeIds 保留
}
```

## 7. API 契约

### `POST /api/goals/:id/resources/auto`

请求：

```json
{ "nodeIds": ["n1", "n2"], "mode": "fill" }
```

- `nodeIds` 缺省：取路径阶段全部节点；
- `mode`：`fill`（跳过已有）| `refresh`（补缺失 + 替换未验证）| `retry`（只重试指定节点）；
- 响应：`text/event-stream`，事件见 FR-5。

### `DELETE /api/resources/:id`

- 删除资源文件；不存在返回 404。

### `GET /api/resources?goalId=...`

- 资源总览；返回 `nodeTitles`、`unverified`、`createdAt`、`relativePath`；
- 缺省返回全部目标。

### 现有接口调整

- `previewResourcesSchema.nodeIds` 的 `.max(5)` 改为 `.max(200)`；
- `POST /resources/search`（预览）保持；
- `POST /resources/commit` 保持，但支持多节点资源；
- `/api/goals/:id/path` 返回扩展 DTO。

## 8. 非功能要求

| 项       | 要求                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 成本     | 单次自动补齐：搜索次数 ≤ 节点数（≤40）；模型判定 ≤ 1 次（无结果时为 0） |
| 延迟     | 40 个节点、并发 3，目标 ≤ 3 分钟；单次搜索超时 10s                      |
| 幂等     | 重复执行 `fill` 不产生重复资源；同一 URL 只建一个文件                   |
| 失败隔离 | 单节点失败不影响其他节点；整体失败才发 `error`                          |
| 可中断   | 客户端断开后停止后续搜索                                                |
| 可测试   | 搜索与 LLM 通过依赖注入替换为 fake，CI 不访问外网                       |
| 兼容     | 旧资源文件、旧路径、旧客户端尽量可读                                    |

## 9. 验收标准

1. AI 生成路径 → 确认落盘 → 自动进度 → 每个节点下出现 1–2 条资源（Tavily 或缺省兜底）；
2. 刷新页面后资源仍在，资源文件位于 `40-资源/`；
3. 没有 Tavily 时出现平台搜索页链接与「未验证」标记；
4. 配置 Tavily 后执行「重新补齐」，未验证链接被真实资源替换；
5. 同一 URL 出现在两个节点下，但资源库只有一个文件；
6. 41 个节点的路径只处理前 40 个并提示；
7. 单节点搜索失败时其他节点正常落盘，失败节点可单独重试；
8. 旧路径点「补齐资源」能补上缺失项；
9. 资源页不再限制 5 个节点，能查看/删除全部资源；
10. 全量测试通过，无外网依赖。

## 10. 风险与依赖

- **Tavily 配额**：自动补齐会显著增加搜索次数；用 40 节点上限与「复用已有」控制；
- **SSE 兼容性**：桌面端/浏览器都支持；反向代理需关闭缓冲（本项目本地直连，风险低）；
- **资源模型迁移**：旧文件只有 `node`，必须保证读取兼容；
- **平台搜索页质量**：兜底链接不是具体资源，需明确标「未验证」，避免用户误解；
- **路径与资源不一致**：节点被删除后资源可能成为孤儿；资源页总览可删除，后续可加清理任务。
