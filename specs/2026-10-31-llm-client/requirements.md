## 2. 范围

### 2.1 范围内

| #   | 交付物                     | 说明                                                                               |
| --- | -------------------------- | ---------------------------------------------------------------------------------- |
| S1  | `src/llm/config.ts`        | 从环境读 base URL / model / 超时 / 重试 / 预算；**不回显、不记录 key**             |
| S2  | 非流式 `chat()`            | OpenAI 兼容 `/chat/completions`，`AbortSignal` 超时，指数退避重试                  |
| S3  | 流式 `streamChat()`        | 解析 `text/event-stream` 增量，可中止；单测覆盖分块与中断                          |
| S4  | 结构化输出 `requestJson()` | zod 校验 + **一次**带错误信息的修复重试；仍失败抛 `LLM_BAD_RESPONSE`（含字段路径） |
| S5  | `POST /api/llm/ping`       | 发一次极小的真实调用，返回 `{ configured, ok, model, durationMs }`；错误按 D4 映射 |
| S6  | 目标页「测试连接」         | 手动触发 ping，显示模型名与耗时；未配置时显示配置指引，不自动调用                  |
| S7  | 契约测试                   | 手写 JSON / SSE fixture，`fetch` 可注入；CI 与本地测试**绝不真调模型**             |

### 2.2 范围外

- 任何真实生成业务（拆解、排路径、搜资源）—— **阶段 5 起**
- SSE 端点（浏览器侧的流式生成）—— 阶段 5
- 多 provider 抽象、本地模型、成本面板 —— 未排期
- 提示词管理平台、缓存、批处理
- 前端设置页（base URL / 模型选择）—— 本期只认环境变量

## 3. 决策

| 编号 | 决策                                                                               | 理由                                        | 影响                                       |
| ---- | ---------------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------ |
| D1   | HTTP 用**原生 `fetch`**                                                            | 零新依赖；超时/中止/SSE 解析都能自己测      | 自己写 SSE 解析与重试                      |
| D2   | 预算按**宽松档**：超时 120s、传输重试 3 次、`max_tokens` 16000、输入上限 100k 字符 | 用户选择；阶段 5 要读教材目录，切太紧会截断 | 单次失败成本更高，靠重试上限与超时兜底     |
| D3   | fixture **手写**最小 JSON / SSE                                                    | 形状稳定、无泄露、模型升级不失效            | 真实响应只在手工冒烟时看                   |
| D4   | 上游错误**统一映射、隐藏细节**                                                     | 不把上游报文与配额信息漏到页面              | 见 §3.2 映射表                             |
| D5   | ping 是 **POST** 且**只有手动触发**                                                | 它是真实调用，会花钱；GET 可能被预取/爬     | 页面必须点按钮才发                         |
| D6   | `fetch` 通过参数注入（默认 `globalThis.fetch`）                                    | 契约测试不联网、可断言重试次数              | `chat()`/`streamChat()` 多一个可选依赖参数 |
| D7   | 传输重试与**结构修复重试分开**                                                     | 前者是网络/5xx，后者是模型输出不合 schema   | 见 §3.3                                    |

### 3.1 配置项（环境变量）

| 变量                      | 默认                       | 说明                                           |
| ------------------------- | -------------------------- | ---------------------------------------------- |
| `DEEPSEEK_API_KEY`        | 无                         | 缺失即「未配置」，ping 返回 `configured:false` |
| `SDL_LLM_BASE_URL`        | `https://api.deepseek.com` | 兼容任意 OpenAI 协议端点                       |
| `SDL_LLM_MODEL`           | `deepseek-chat`            | 与 `/api/health` 一致                          |
| `SDL_LLM_TIMEOUT_MS`      | `120000`                   | 单次请求                                       |
| `SDL_LLM_MAX_RETRIES`     | `3`                        | 传输层重试次数（不含首次）                     |
| `SDL_LLM_MAX_TOKENS`      | `16000`                    | 请求体 `max_tokens`                            |
| `SDL_LLM_MAX_INPUT_CHARS` | `100000`                   | 输入总字符上限，超出直接拒绝                   |

### 3.2 错误映射

| 上游情形                           | 我方 code            | HTTP                               |
| ---------------------------------- | -------------------- | ---------------------------------- |
| 未配置 key                         | `LLM_NOT_CONFIGURED` | 200（`configured:false`，仅 ping） |
| 401 / 403                          | `LLM_AUTH`           | 502                                |
| 429                                | `LLM_RATE_LIMIT`     | 429                                |
| 5xx / 网络错误                     | `LLM_UPSTREAM`       | 502                                |
| 超时                               | `LLM_TIMEOUT`        | 504                                |
| 输出不合 schema（修复后仍失败）    | `LLM_BAD_RESPONSE`   | 422                                |
| 输入超过 100k 字符（**不发请求**） | `LLM_BAD_INPUT`      | 400                                |

响应体只给 `{ error: { code, message } }`；message 里**不得**出现 key 片段、上游原始报文、请求头。

### 3.3 两种重试，别混

- **传输重试**：网络错误 / 5xx / 429，最多 `SDL_LLM_MAX_RETRIES` 次，退避 500ms × 2^n（带抖动），可被调用方中止。
- **结构修复重试**：zod 校验失败时，把「哪几个字段错了」拼进第二轮 user 消息，**只重试一次**；再失败即 `LLM_BAD_RESPONSE`。

## 4. 上下文与约束

| 项         | 内容                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 使命约束   | R2 模型不直接写文件（本阶段只返回文本/JSON，不落盘）；R4 key 只在服务端；R3 失败要响                                     |
| 技术栈约束 | ESM + NodeNext；TS strict；`web/` 独立 tsconfig；共享类型只导类型                                                        |
| 运行时     | 本机 Node 24；CI Node 22 / 24（`fetch`、`AbortSignal` 均可用）                                                           |
| 测试       | 现有 201 用例必须保持；新增用例不得依赖网络                                                                              |
| 分支       | 从 `main`（b7e8a0e）切出；`.git` 已改为指向本地盘的 gitdir 指针                                                          |
| 密钥       | 用户选择「现在就给 key 做真实冒烟」，但 key **不写进仓库、不贴进聊天**：放环境变量或 `.env.local`（需加进 `.gitignore`） |

## 5. 风险

| 风险                       | 缓解                                                                        |
| -------------------------- | --------------------------------------------------------------------------- |
| 真实调用烧钱 / 卡住        | ping 上限 `max_tokens: 1`；120s 超时；只手动触发                            |
| 测试误联网                 | `fetch` 注入 + 默认在测试里指向一个会抛错的假实现；CI 无 key                |
| SSE 分块边界（一行被切开） | 按字节缓冲、只处理完整行；单测覆盖「半行到达」                              |
| 上游协议漂移               | 只依赖 `choices[0].message.content` 与 `usage`；缺字段按 `LLM_BAD_RESPONSE` |
| 密钥泄露到日志/错误        | 日志只打 model / 状态码 / 耗时；错误 message 过一遍脱敏                     |
| 宽松预算导致一次失败很贵   | 重试退避 + 上限 3；阶段 5 再按场景下调                                      |

## 6. 未决问题

1. 真实冒烟的 key 怎么交付：本期**只读进程环境变量**（`$env:DEEPSEEK_API_KEY`），不实现 `.env` 加载器——
   避免把密钥读进一个可能被误提交的文件。key 不进仓库、不进聊天记录。
2. ping 的提示词与 `max_tokens`：本期用「回复一个字符」+ `max_tokens: 1`，若 DeepSeek 要求 ≥ 某些值再调。
3. 是否在 `/api/health` 里回显「上次 ping 时间」—— 本期不做，避免把一次性检查变成状态。
