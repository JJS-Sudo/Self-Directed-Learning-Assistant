- 3 个节点 → `preview` 返回 **6 条候选**（每节点 2 条），元数据齐全，`warnings: []`；
- `commit` → `created: 6`；再次提交同一批 → `created: 0`，**6 条全部 skipped**，reason 分别为「已存在于「R²与拟合优度 / 高斯-马尔可夫定理 / 最小二乘估计」」；
- `GET /resources`：6 条，`score` 与 `rankReason` 实时生成（水平 +3 / 媒介 +2 / 时长 +1）；
- 页面 `/resources`：6 条资源、理由可见、画像显示「入门 / 视频 / 每周 5 小时」。

与计划的偏差：

1. **元数据 schema 从 enum 改成 string + 逐项校验**：enum 会让一条非法值触发「修复重试」并可能整批失败，
   与 D6「非法字段丢弃并警告」冲突。现在一条坏值只丢它自己。
2. **Vite 增加了 `@shared` alias**：之前 `@shared/*` 只被**类型导入**使用（构建时被擦除，不需要解析）；
   本阶段首次从共享模块导入运行时值（UI 词表），Rollup 立刻报「无法解析」——补了 `resolve.alias`。
3. **画像时长的单位纠正**：领域层 `rankReasonOf` 用 `timeBudget * 60` 比较，说明 `time_budget` 是**小时**；
   页面原先写成「分钟」，已改为「每周 N 小时」。

### 两个真实环境才会暴露的发现

1. **相关性不是元数据能解决的**：Tavily 对「R² 拟合优度」返回了 GraphPad Prism、SPSSPRO、
   Google Earth Engine 这类弱相关页。模型只判「等级/媒介/时长」，不判「是否讲这一节」，
   所以**必须靠人工勾选**——这与 D1「人工勾选后落盘」一致，但不能指望自动全收。
2. **「没搜到」在真实 Tavily 上几乎不会触发**：用自造标题 `zzz_qwerty_不存在的概念_987`
   检索，仍然返回 5 条（无关）结果。`found: 0` 只在供应商返回空数组时出现，现有单测覆盖了这条分支，
   但真实引擎的行为是「永远给点什么」。若要按相关性拦截，需要另加阈值（超出本阶段范围）。

未完成：无（T5.2 已闭环）。
