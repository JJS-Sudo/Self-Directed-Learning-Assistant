## 2. 验收场景

### V1 · 检索（临时库，3 个节点）

1. 资源页选目标 → 勾 3 个节点 → 「检索候选」；
2. 每个节点 5 条以内候选，带标题/URL/摘要；
3. 候选上的 level / media / duration 已预填（模型判定），可改。

### V2 · 落盘与去重

1. 勾选 4 条 → 「落盘所选」→ `created: 4`；
2. 再检索一次同一节点、勾同一条 → `skipped: 1`，reason 里指出已挂在哪个目标。

### V3 · 理由与画像一致

1. `GET /api/goals/:id/resources`：每条有 `score` 与 `rankReason`；
2. 改画像（媒介偏好 视频 → 文字）后再取：理由/分数变化；
3. 磁盘上的资源文件 **不应** 被这次读取改写（`rank_reason` 不落盘）。

### V4 · 无结果

- 搜一个冷门节点（例如自造标题）→ `perNode.found: 0` + 警告「没搜到」；
- 页面显示提示，不是报错、不是空白。

### V5 · 未配置

```bash
# 摘掉 TAVILY_API_KEY
curl -s -o - -w "\n%{http_code}\n" -X POST localhost:3000/api/goals/<id>/resources/preview \
  -H "content-type: application/json" -d '{"nodeIds":["n1"]}'
```

- 503 `SEARCH_NOT_CONFIGURED`；
- 网络面板没有 `api.tavily.com` 请求。

### V6 · 真实冒烟

在 `%TEMP%` 的临时库上跑 V1 + V3 + V4，记录：

- 检索节点数 / 候选数 / 实际搜索次数；
- 3 个节点落盘条数；
- 理由是否体现画像（媒介偏好、水平、时长）；
- 真实运行库 `git status` 无变化。

## 4. 不通过的样子

- 把供应商没返回的 URL 写进库（编造/拼接链接）。
- 元数据不校验：`level: "高级"`、`media: "播客"`、`durationMin: "约 20 分钟"` 落盘。
- 重复 URL 落盘两次，或去重时不说明挂在哪个目标。
- 页面读 `rank_reason` 字段而不是实时计算（改画像后理由不变）。
- 无结果返回 500 或空列表却没有任何提示。
- 未配置 Tavily 仍然发起请求。
- 一次预览超过 5 个节点或超过 5 次搜索。
- 真实冒烟写进真实运行库。

## 6. 评审者 5 分钟检查单

1. 检索一次：请求 query 里有没有节点名与目标名？
2. 落盘后再落盘同一条：是 `skipped` 还是多了一条？reason 说得清挂在哪儿吗？
3. 改画像的媒介偏好，理由变了吗？
4. 冷门节点：是「没搜到」还是 500？
5. 摘掉 Tavily key：几秒内返回 503，且没有外网请求吗？
6. 冒烟后：真实运行库 `git status` 干净吗？
