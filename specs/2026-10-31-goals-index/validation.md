## 2. 验收场景

### V1 · 创建与刷新

```bash
npm run dev     # 浏览器 3000
```

1. 在目标页填：标题「三天搞懂 SQLite 索引」、类型「激励性」、期限（未来 3 天）、成功判据一句话；
2. 提交 → 列表出现该目标，剩余天数 = 3；
3. 刷新（F5）→ 目标仍在；
4. `curl -s localhost:3000/api/goals | head` → JSON 里能看到它。

### V2 · 删索引自愈（不重启）

```bash
rm 自我导向学习项目运行库/.sdl-index.db*
curl -s localhost:3000/api/goals     # 仍应返回全部目标
```

- 响应内容与删除前一致；
- 索引文件被重新创建；
- 进程日志里出现「重建 N 个目标」一类记录。

### V3 · 改 Markdown，索引跟随

用编辑器把某个目标标题改掉（只改 frontmatter 的 `title`，**不改文件名**；或按 SOP 改文件名与链接）：

- 刷新网页 → 新标题出现；
- 说明快照（mtime / 文件数）触发了重建。

### V4 · 错误可见

| 输入                               | 期望                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| 标题留空                           | 表单下方显示「title 不能为空」一类错误；`10-目标` 不新增文件 |
| 类型选「激励性」、期限留空         | 显示「激励性目标必须给期限」；不新增文件                     |
| 日期填非法值（用 curl 直接打 API） | 400 + `INVALID_INPUT`                                        |

### V5 · `npm run index`

```bash
npm run index
```

- 输出「重建 N 个目标」与索引路径；
- 连跑两次，N 相同（幂等）。

### V6 · 生产模式

```bash
npm run build && npm start
```

重复 V1 与 V2：创建、刷新、删索引、刷新 —— 行为与 dev 一致。

### V7 · 不污染版本库

```bash
git status --short
```

- 看不到 `.sdl-index.db`、`.sdl-index.db-wal`、`.sdl-index.db-shm`；
- `.gitignore` 里有对应规则。

## 4. 不通过的样子

- 索引写失败被吞掉，接口仍返回成功且列表少一条。
- 把 `days_left` 存进索引（跨天就错），而不是读取时算。
- 删掉 `.db` 后必须重启才恢复 —— 证明请求路径没有自愈。
- 改了 Markdown 而列表不动（快照判定失效）。
- 每次启动都全量重建（虽然能跑，但违背「快照判定」的设计，库大时启动会慢）。
- `.sdl-index.db` 被提交进仓库。
- 表单把 API 错误变成「提交失败」四个字，用户不知道错在哪。
- 为了让测试通过而放宽既有 187 条断言。

## 6. 评审者 5 分钟检查单

1. `npm ci && npm run dev`，建一个目标，刷新：还在吗？
2. `rm 自我导向学习项目运行库/.sdl-index.db*`，**不重启**，刷新页面：列表回来了吗？日志里有重建记录吗？
3. 用编辑器改一个目标标题，刷新：列表变了吗？
4. 提交空标题、以及「激励性 + 无期限」：错误看得懂吗？`10-目标` 有没有多出文件？
5. `git status --short`：有没有 `.db` 混进来？
