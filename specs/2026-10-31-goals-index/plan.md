## 实施记录（2026-10-31）

T1–T6 全部完成；用例从 187 增至 **201**（索引 6 + API 8）。

| 项       | 结果                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 索引     | `better-sqlite3`，库根 `.sdl-index.db`，`user_version` 迁移，`meta.source_stamp` 快照 |
| 连接策略 | **每次请求开关连接**（原计划进程内缓存）                                              |
| API      | `GET /api/goals`（新→旧）、`POST /api/goals`（zod → 落盘 → 索引）                     |
| CLI      | `npm run index` 输出「重建 N 个目标 · 索引路径」                                      |
| 前端     | 表单 + 列表（标题 / 类型 / 期限 / 剩余天数）+ 三态 + 错误原样展示                     |

实测证据：

- 建目标 → 列表立即出现，`daysLeft` 5（期限 2026-11-05）；
- 刷新页面仍在；`GET /api/goals` 与页面一致；
- **删 `.sdl-index.db` 后不重启**：下一次 `GET` 自动重建并返回全部 3 条，索引文件被重新创建；
- 改 Markdown 里的 `title` → 下一次 `GET` 就返回新标题（快照触发重建）；
- `npm run index` 输出 3；
- 逾期目标显示「已逾期 20 天」，常规目标只显示一次「无期限」。

**T6.4 生产模式回归（补齐）**：`npm start`（PORT=3100、`dist/web` 已构建）下：

- `/`、`/resources`、`/nope` 均返回 413 字节的 SPA 外壳；`/api/goals` 返回 JSON；`/api/nope` 仍是 JSON 404；
- 网页里新建「生产模式建的目标」→ 列表立即出现（4 条），刷新仍在；
- **删 `.sdl-index.db` 后不重启、只刷新页面**：4 条全部回来，索引文件被重建；
- 标题只填空格提交 → 表单显示「title：不能为空」，列表条数不变（未落盘）。

与计划的三处偏差：

1. **连接不缓存**：Windows 上常开的 SQLite 句柄会锁住文件，用户「删索引看自愈」时删不动——
   而那正是本阶段的验收场景。改成每次请求 `open → 校验 → 用 → close`。
2. **`tests/web-scope.test.ts` 移除了 `/api/goals`**：该用例原本断言「所有 JSON API 不存在」，
   阶段 3 合法新增了这一个入口；其余 9 条 404 断言原样保留，并把用例标题改成「旧入口边界」。
3. **Vite watcher 忽略 `*.tmpdir`**：在 OneDrive 上编辑文件时，原子写的临时目录会让 watcher
   抛 `EBUSY` 直接杀掉 dev server。已在 `vite.config.ts` 里忽略这些路径——这是环境补丁，不是功能改动。

另修一处 UI 小问题：无期限目标的元信息原先显示两次「无期限」。
