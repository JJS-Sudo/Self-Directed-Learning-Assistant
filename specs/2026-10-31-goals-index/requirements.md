## 3. 决策

| 编号 | 决策                                                            | 理由                                                           | 影响                                                                         |
| ---- | --------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| D1   | **只做创建 + 列表**                                             | 把「写入 → 落盘 → 索引 → 重建」这条链跑通，比堆 CRUD 更有价值  | 无编辑/归档按钮                                                              |
| D2   | 索引**只建 `goals` 表** + 版本化迁移骨架                        | 空表没有写入路径只是噪音；迁移骨架先立起来，后续阶段加表不返工 | `user_version` + 有序迁移数组                                                |
| D3   | 列表字段：标题 / 类型 / 期限 / 剩余天数                         | 一屏能判断「什么时候到期」                                     | 成功判据不进列表（长文本），只在表单里                                       |
| D4   | 驱动 **`better-sqlite3`**                                       | 本机实测可用；同步 API 简单；tech-stack 首选                   | 原生模块，Docker 阶段要 debian 基底                                          |
| D5   | **只给 HTTP 边界加 zod**                                        | 领域层已有 `VaultError` 校验，职责不混                         | 新增 `zod` 依赖；zod 错映射成 `INVALID_INPUT`                                |
| D6   | 索引在**库根 `.sdl-index.db`**，缺失即重建                      | 随库走、删掉不丢数据；验收最容易演示                           | 库目录多一个被忽略的文件                                                     |
| D7   | 剩余天数按**本地自然日**                                        | 与 `daysLeftOf()` 现有语义一致                                 | 索引里存 `deadline` 字符串，天数读取时算 —— 不存「算好的天数」，否则隔天就错 |
| D8   | 新鲜度用**源目录快照**（max mtime + 文件数）                    | 比每次全量扫文件便宜，又比「只在缺失时建」更不容易过期         | 在 Obsidian 里改目标后，下一次请求会重建                                     |
| D9   | 列表顺序在 **API 层倒序**（新→旧），领域层保持 `createdAt` 升序 | 列表直觉与领域层职责分开；领域层顺序被 187 个用例依赖，不动它  | API 返回前反转；领域层零改动                                                 |

### 3.1 索引表（本期定稿）

```sql
-- user_version = 1
create table meta (key text primary key, value text not null);
create table goals (
  id              text primary key,
  title           text not null,
  kind            text not null,
  status          text not null,
  deadline        text,
  success_criteria text,
  created_at      text not null
);
```

`meta` 里存 `source_stamp`（`<maxMtimeMs>:<count>`）与 `built_at`。
**不存 `days_left`**：它是日期的函数，存下来必然过期。

### 3.2 写路径的顺序

1. zod 校验请求 → 2. `createGoal()` 写 Markdown（唯一真相）→ 3. 更新索引行。
   第 3 步失败时：立刻尝试一次全量重建；仍失败则返回 **500 + `index_error`**，
   但 Markdown 已经写成 —— 响应里明说「目标已创建，索引未更新」，不静默降级（mission R3）。

## 5. 风险

| 风险                                        | 缓解                                                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 索引与 Markdown 漂移（在 Obsidian 里改/删） | 快照判定：mtime 或文件数变化即全量重建；删库文件也会重建                                                |
| 索引写失败导致列表少一条                    | 写后立即 `upsert`；失败则重建一次，仍失败返回 500 并明说「目标已创建」                                  |
| 原生模块在 CI 上装不上                      | CI 用 `npm ci`，`better-sqlite3` 预编译覆盖 ubuntu x64；若失败则回退到 `npm rebuild` 并在 CI 里单独一步 |
| 同一进程内多次打开同一库                    | 进程内按库根缓存 `{db, stamp}`；请求级只做 stamp 比较                                                   |
| 时区导致「剩余天数」差一天                  | 复用 `daysLeftOf()`，不新写日期运算；测试固定 `today` 注入                                              |
| 索引文件被误提交                            | `.gitignore` 加 `/自我导向学习项目运行库/.sdl-index.db*` 与本机默认库路径                               |
