# 使命（Mission）

> 状态：**生效**，版本 1.0（2026-10-29）
> 本文是项目的**最高约束**。与 `README.md` / `START-HERE.md` / `SOP.md` 冲突时，以本文为准（冲突清单见第 7 节）。
> 决策来源：2026-10-29 的三轮访谈（使命 / 技术栈 / 路线图），原始回答摘要见附录 A。

---

## 1. 一句话使命

**把「想学」变成「学完」：用户只给出目标与验收标准，产品在网页里产出并维护完整的学习结构
（知识地图 → 学习路径 → 资源 → 验收 → 复盘），且每一步产物都可校验、可修改、可导出。**

它仍然**不生产教学内容**——它生产的是**结构与判据**，内容来自用户给的材料与联网检索到的真实资源。

---

## 2. 这次转向改了什么（必读）

旧版的产品定位是「一个人 + 工作区 Agent + Obsidian 的私人书架」，明确写着
「不联网、不调用大模型、可视化交给 Obsidian」。本次访谈把定位改成了**面向陌生人的网页产品**：

| 维度     | 旧（README / SOP 的写法）         | 新（本文生效）                                               |
| -------- | --------------------------------- | ------------------------------------------------------------ |
| 交付面   | 网页只两条入口，其余全在 Obsidian | **网页承载全部功能**，Obsidian 只是可选导出目标              |
| 智能来源 | 工作区里的 Agent，软件零 AI       | **软件内建 DeepSeek 调用**，Agent 变成「高级用户的可选旁路」 |
| 联网     | 明确不做                          | **允许**：联网检索资源、校验链接                             |
| 受众     | 作者本人 + 自己的 Agent           | **有明确主题和截止日期的自学者**（不懂自学方法论）           |
| 分发     | 拿源码跑起来                      | **GitHub 开源 + 一键运行**（Docker Compose / npm）           |

> 一句话：**产品从「Agent 的书架」变成「替学习者干活的整机」。**
> 保留下来的是原项目最硬的那块资产：**领域层、写入边界、四类覆盖检查（可度量的质量闸门）**。

## 3. 目标受众

### 3.1 主要用户（唯一需要为它做取舍的人）

**截止日期驱动的自学者**：

- 有一个具体主题（一门课的一章、一次转岗要用的技能、一个项目要补的知识），**有期限**；
- **不具备**自我导向学习的方法论（不会拆知识网、不会排路径、不知道什么叫「可判定的验收」）；
- 愿意在网页上点、填、确认，**不愿意**先学 Obsidian、双链、frontmatter；
- 判断产品好坏的标准很朴素：**「我输入一句话目标，它给我的东西我能不能直接用。」**

### 3.2 次要用户

| 谁                      | 要什么                                   | 产品要给的最小支持                               |
| ----------------------- | ---------------------------------------- | ------------------------------------------------ |
| 方法论熟练者 / 技术用户 | 不想被黑盒生成绑架，要审阅、改写、版本化 | 生成物落到 Markdown，可编辑；全库导出            |
| Agent / CLI 用户        | 用脚本或自己的模型驱动                   | 稳定的 HTTP API 与 CLI，与网页同一套写入路径     |
| 研究者 / 教学者         | 看这套方法怎么工作                       | 生成过程可解释（为什么这样拆、覆盖检查报了什么） |

### 3.3 明确不是受众

课堂与机构的多用户教学、内容消费者（想直接看课的人）、移动端重度用户、需要社区与社交的学习者。

## 4. 成功的判据（可度量）

按优先级排序，前两条是「这个产品成立」的最低线：

1. **端到端成立**：一个新用户只输入「目标 + 验收标准」，**10 分钟内**在网页里拿到可交互的知识地图与学习路径，**全程不需要手写或手改任何数据文件**。
2. **结构合格**：生成后 `四类覆盖检查` 全部为空的比例 ≥ 80%（抽检 20 个真实主题），不合格时页面显式给出警告，而不是静默产出一张看起来完整的图。
3. **数据不锁死**：删除索引库后功能不退化（可全量重建）；任意时刻能一键导出全库为纯 Markdown。
4. **降级可用**：没有 API key、断网时，仍能浏览、编辑、手动建实体，核心页面不白屏、不 500。
5. **一键可用**：干净机器上 `docker compose up` 到浏览器可用 ≤ 5 分钟；CI 五项（typecheck / lint / unit / e2e / docker build）全绿。

> 反面判据（出现即视为失败）：为了「看起来能跑」而吞掉生成错误；为了演示顺利而手改样例库；
> 为了功能数量而牺牲「产物可校验」这一条。

## 5. 设计原则

1. **模型不写文件。** 大模型只产出**经 schema 校验的结构化候选**（节点、路径段、题目、资源候选）；
   命名、链接、日期、落盘位置、覆盖检查全部由**确定性代码**执行。模型是「提案者」，不是「写者」。
2. **结构可校验，内容不冒充正确。** 产品能保证「没有脱节的节点、没有学不到的资源」；
   它不保证「这个知识点拆得适合你」——后者必须让用户看见并否决。
3. **生成物是草稿，不是判决。** 每一屏生成结果都要能改、能重生成、能删，且改动立刻反映到下游。
4. **失败要响。** 解析失败、覆盖检查不通过、检索无结果，一律显式呈现 + 给出下一步动作；禁止静默降级成「空白但成功」。
5. **数据归用户。** Markdown 为唯一真相；任何索引都是可丢弃的缓存；导出不是付费功能。
6. **成本可见。** 每次生成显示 token 用量与预估费用；单目标默认预算上限可配置。
7. **单机优先。** 默认单实例、单用户、本地文件；要上公网必须显式打开访问口令，不能靠「应该没人扫到」。

## 6. 红线（不因便利而破）

| #   | 红线                            | 违反的样子                                   |
| --- | ------------------------------- | -------------------------------------------- |
| R1  | Markdown 是唯一真相，索引可重建 | 只把数据写进 SQLite，导出变成「另存为」      |
| R2  | 模型不直接落盘                  | 让 LLM 直接输出文件内容并按字符串拼进 vault  |
| R3  | 不静默失败                      | 生成不合规时返回 200 + 空地图                |
| R4  | API key 只在服务端              | key 出现在前端 bundle、URL、日志或导出文件里 |
| R5  | 无 key 可降级运行               | 一进首页就因缺 key 抛 500                    |
| R6  | 写入不越库根                    | 任何路径拼接不校验就写盘                     |

**以下不是红线，是「当前版本不做」**（改主意需要一次 ADR，而不是顺手加）：
账号体系与多租户、社区/社交、移动端原生 App、托管教学内容、付费订阅、多人实时协作。

## 8. 已知张力（不假装解决）

1. **「10 分钟拿到可用的图」与「不生产教学内容」有张力。** 模型只能拆结构，材料质量决定拆解质量；产品必须主动索取材料（目录/大纲），不能假装知道。
2. **「陌生人一键用」与「DeepSeek/搜索 API 要 key」有张力。** 缓解方式是：无 key 时仍可手动走完全流程，并把「去申请 key」做成三步引导，而不是报错。
3. **「结构可校验」很容易被误读成「内容正确」。** 界面文案必须区分「结构完整」与「内容适用」，否则用户会盲目信任。
4. **生成成本对无收入的开源项目是真实约束。** 默认预算 + 便宜的二次操作（只重排路径、只补一题）是必需的，不是优化项。
