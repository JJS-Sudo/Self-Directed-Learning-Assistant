# 路线图（Roadmap）

> 状态：**生效**，版本 1.0（2026-10-29）
> **输入说明**：仓库中**没有 `TODO.md`**（已全库搜索确认）。本路线图的输入是
> `SOP.md` 第 8 节的 7 条已知限制 + `specs/mission.md` 的转向 + 2026-10-29 访谈第三轮的回答。
> 排序按「风险先于体量」：**先把最不确定的一环（模型生成质量）用最薄的线打通，再长肉。**

阶段是刻意切小的 —— 每一片都应当是可交付、可独立评审与测试的工作。

**阶段完成定义（DoD）**：`typecheck` + `lint` + `unit` 全绿；演示路径当场可复现；不破
`specs/mission.md` 第 6 节的红线；新增写盘路径必须过 `vault/` 的守卫。

> **进度标记**：`✅` = 已完成并合入 `main`（截至 2026-11-04：阶段 1–12 全部完成，roadmap 收尾）。未标记的是待做。

---

## 阶段 1 —— Hello Hono ✅

- `git init`，加 ESLint(flat) + Prettier，GitHub Actions 先跑 `typecheck` + `lint` + `test`（现有 172 个用例必须仍全绿）。
- 建 `web/`（Vite + React），dev 时由 Hono 代理 `/api`，生产由 Hono 托管 `dist/web`。
- `GET /api/health` 返回库状态 / 索引状态 / 模型是否配置；`/` 返回一张 Hello 页并显示这三项。
- **演示**：`npm run dev` → `localhost:3000` 显示 Hello + `vault: ok` + `model: 未配置`。

## 阶段 2 —— 基础布局 ✅

- 六区导航（目标 / 地图 / 路径 / 资源 / 验收 / 复盘）与每区的空状态。
- 设计令牌沿用现有亮暗主题与单强调色；页面无第三方字体/脚本/CDN 请求。
- 客户端路由支持深链与刷新（不 404），页内 404 兜底。
- **演示**：六个区都可直达、刷新不丢、DevTools 网络面板零外部请求。

## 阶段 3 —— 目标：录入、落盘、索引可重建 ✅

- `POST /api/goals`（复用 `createGoal`，加 zod），**先写 Markdown，再写索引**。
- 建 SQLite 索引表（`goals` / `nodes` / `stages` / `resources`），启动时校验，`npm run index` 全量重建。
- 目标列表读索引；删掉 `.sdl-index.db` 后列表自动重建。
- **演示**：新建目标 → 刷新仍在 → 删除索引文件 → 列表自动恢复。

## 阶段 4 —— DeepSeek 客户端与契约 ✅

- `llm/` 客户端：OpenAI 兼容端点、流式、超时、指数退避、单次调用 token 预算。
- zod schema 校验 + **一次**带错误信息的修复重试；仍失败返回 422 并指出字段路径。
- 用录制 fixture 做契约测试（CI 绝不真调模型）；`/api/llm/ping` 用于自检。
- **演示**：配 key 后 ping 返回模型名与耗时；不配 key 时页面提示「未配置」而不是 500。

## 阶段 5 —— 拆解：目标 → 知识网（最薄的端到端纵切） ✅

- 先索取材料（目录 / 大纲），按小节分块生成候选节点（`temp_id`），**只返回候选、不落盘**。
- 确认后由领域层落盘：生成 6 位 `id`、拼 wikilink、清洗标题、排序 `order`。
- 生成后自动跑四类覆盖检查；地图页用 React Flow 渲染，警告与图并列显示。
- **演示**：一句目标 + 粘贴教材目录 → 5–15 个节点的可拖拽图；结构不合格时显式红字警告。

## 阶段 6 —— 路径与验收题 ✅

- 节点 → `PathStage`：每段 `nodes` ≥1、`estimate`、`order`，`checks` 至少一条且可判定。
- 把「每段至少一条检验信号」下沉到写盘前的领域校验，**所有入口共用**（修 SOP 第 8 节第 2 条）。
- 每段生成 1 道封闭题（`answer` + 正文受管区块解析），路径页展示段—节点—题的对应。
- **演示**：路径覆盖 100% 叶子节点，覆盖警告为 0。

## 阶段 7 —— 资源检索与排序 ✅

- `SearchProvider` + Tavily：按节点检索 top-N 候选，只记录真实返回的 URL。
- 人工勾选后落盘 `40-资源/`，补齐 `level` / `media` / `duration_min`。
- 资源站沿用三因子排序并**实时**显示理由（不依赖存下来的 `rank_reason`）。
- **演示**：为 3 个节点补齐资源，排序理由与画像一致；无结果时明确说「没搜到」。

## 阶段 8 —— 验收与复盘（把六环闭上） ✅

- `POST /api/assessments`：做题 / 复述两种模式，**「未作答」也必须落一条记录**。
- `POST /api/retrospectives`：`worked` / `failed` / `next_adjustment` / `adjust_events`。
- 复盘后回写 `mastery`（未学 → 在学 → 已掌握），并展示本轮调整改变了哪几段。
- **演示**：全程不开编辑器，跑完「学 → 测 → 复盘 → 改路径」一轮。

## 阶段 9 —— 一键跑起来 ✅

- 多阶段 `Dockerfile` + `compose.yml`，`/data` 卷，**默认只绑 `127.0.0.1`**；`HOST=0.0.0.0` 时无 `SDL_ACCESS_TOKEN` 拒绝启动。
- npm `bin` 入口 + `.env.example`（`DEEPSEEK_API_KEY` / `TAVILY_API_KEY`）。
- CI 增加 Playwright 主路径用例与 `docker build`。
- **演示**：干净机器 `docker compose up` 到浏览器可用 ≤ 5 分钟；CI 五项全绿。

## 阶段 10 —— 质量闸门与兜底 ✅

- 生成质量面板：四类警告汇总、失败原因、**只重生成受影响的子图**。
- 全库导出 Markdown zip（`.canvas` 作为可选兼容产物），支持导入旧库。
- token / 费用面板，单目标预算可配置。
- **演示**：导入 `自我导向学习项目运行库/` 里的三个真实项目，地图与路径正常渲染、警告可见。

## 阶段 11 —— 开源准备 ✅

- **干净的发布仓库**：另起一个新仓库，或用 `git filter-repo` 抹掉 `自我导向学习项目运行库/` 的历史，
  发布版只保留 `seeds/` 演示库；确认历史里没有私人学习数据与任何 key。
- **首启自动建库**：`.sdlrc.json` 不再指向运行库（改成 `./vault` 或删掉），首次启动自动创建空库与骨架；
  新克隆不需要任何手工配置就能建第一个目标。
- **重写 README 开头**：环境要求（Node ≥ 22 / Docker）、Docker 与 Node 两条启动路径、API key 与费用说明、
  页面截图或 GIF；把「怎么开始」放在最前面。
- **`START-HERE.md` 改成「5 分钟上手」**：删掉过时的「阶段 1、六区、拆解靠手写 SOP」描述，
  只留今天真实可用的路径。
- **已定授权**：PolyForm Noncommercial 1.0.0（源码可见、非商业免费；商用需单独授权，微信联系）。
- **已定发布**：GitHub + Gitee 双发同一份干净快照；不做便携包（安装包留给阶段 12）。
- **演示**：全新克隆 → 按 README 启动（Docker 或 Node）→ 用 seeds 演示库跑通七区 → 不碰任何私人数据。

## 阶段 12 —— 零安装桌面应用（Electron） ✅

- **Electron 主进程内嵌服务**：主进程起现有 Hono 服务（`createApp`）并开 `BrowserWindow` 指向
  `http://127.0.0.1:<动态端口>`；端口被占用时自动换一个，不要求用户理解端口。
- **数据目录**：安装版 `userData/vault`；Windows portable 与 Linux AppImage 用程序旁 `data/vault`；
  首次从 `seeds/` 初始化；菜单提供「打开数据目录 / 导入 zip / 导出 zip」。
- **密钥**：沿用「API Key」页与库根 `.sdl-secrets.json`；桌面版用 `safeStorage` 加密，旧明文自动迁移，
  不写进 Electron 配置或安装包。
- **原生模块**：`better-sqlite3` 按 Electron ABI 重建（`@electron/rebuild`），CI 里固定流程。
- **打包**：`electron-builder` 出 Windows NSIS + portable、macOS dmg + zip、Linux AppImage + zip；
  单实例、外部链接交给系统浏览器、渲染进程禁用 Node 集成。
- **更新**：`electron-updater` 以 GitHub Releases 为主源、Gitee 为回退；mac 未签名时只提示手动下载。
- **演示**：CI 的 Windows 冒烟——打包后启动 `release/win-unpacked` → 自动建库 → 监听本地端口 →
  `/healthz` 返回 200；三平台同轮出包。

## 为什么是这个顺序

1. **阶段 1–2 先付基建账**，因为后面每一片都要靠 CI 与导航来演示。
2. **阶段 3 先让「目标」真正落盘可重建**，它同时验证了「Markdown 是真相、索引是缓存」这条红线，成本最低。
3. **阶段 4 单独做模型层**，把最不确定的东西（JSON 合规、超时、费用）隔在一个可测试的壳里。
4. **阶段 5 是全项目最关键的 PR**：端到端最薄纵切通了，产品就成立；不通，后面全部推迟。
5. **阶段 6–8 按六环顺序补**，每补一环就多一个「不用编辑器」的理由。
6. **阶段 9 把「陌生人一键用」变成可验证事实**，而不是口号。
7. **阶段 10 收口质量与迁移**，因为此时已经有足够多的真实数据可导入、可回归。
