> 状态：**生效**，版本 1.0（2026-10-29）
> 依据：`specs/mission.md` 的定位 + 2026-10-29 访谈第二轮的选型回答。

## 1. 一句话

**一个单进程的 Node 应用：Hono 提供 API 与 SPA 宿主，React 在浏览器里渲染知识图；数据是用户磁盘上的 Markdown 库，SQLite 只做可丢弃的索引；DeepSeek 负责生成结构化候选，Tavily 负责找真实资源。**

```
浏览器 (React + React Flow)
   │  JSON / SSE
   ▼
Hono 4 (Node ≥22)
   ├── domain/     纯函数：实体校验、四枝干、三因子排序、覆盖检查   ← 复用现有资产
   ├── vault/      文件读写、路径守卫、ID、重置                     ← 复用现有资产
   ├── llm/        DeepSeek 客户端 + zod 校验 + 一次修复重试        ← 新增
   ├── search/     Tavily 适配器                                   ← 新增
   ├── index-db/   SQLite 索引（可全量重建）                        ← 新增
   └── export/     Markdown zip / Obsidian .canvas                 ← 由现有 maps/ 降级而来
        │
        ▼
   用户库（Markdown + frontmatter，唯一真相）
```

## 3. 选型清单

### 3.1 前端

| 决策     | 选择                                                                   | 理由 / 代价                                                                                                                                                     |
| -------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 构建     | **Vite 7**（+ `@vitejs/plugin-react` 5）                               | 与 Hono 同仓、dev 代理简单；不引入 SSR 框架。**Vite 8 的 rolldown 在中文 + OneDrive 路径下加载配置失败，已回退**（见 `2026-10-31-hello-hono/plan.md` 实施记录） |
| UI       | **React**（最新稳定）                                                  | 访谈确认；生态里 React Flow 质量最高                                                                                                                            |
| 图可视化 | **React Flow（`@xyflow/react`）**                                      | 访谈确认；节点拖拽/缩放/自定义节点开箱即用，55 节点量级完全够                                                                                                   |
| 路由     | **React Router**（或 TanStack Router）【建议】                         | 六区导航需要深链与刷新不 404；二者择一，倾向 React Router                                                                                                       |
| 样式     | **原生 CSS + CSS 变量设计令牌**（沿用现有亮/暗主题与单强调色）【建议】 | 不引入 Tailwind/CSS-in-JS，减少构建与迁移成本；**可复议**                                                                                                       |
| 状态     | **React Query（TanStack Query）** + 局部 `useState`【建议】            | 生成/轮询/缓存是主要复杂度，不需要 Redux                                                                                                                        |

**不引入**：Next.js / SvelteKit / Remix（SSR 对本产品无收益，且会重写路由与视图）。

### 3.2 数据

| 决策     | 选择                                                                             | 理由 / 代价                                                                                    |
| -------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 真相     | **Markdown + YAML frontmatter**                                                  | 访谈确认；可读、可版本化、可导出；已有 172 个用例的读写契约                                    |
| 索引     | **SQLite**，单文件，WAL 模式                                                     | 访谈确认；免运维、可随库一起备份                                                               |
| 驱动     | **`better-sqlite3`**【建议】                                                     | 同步 API 简单、预编译包覆盖主流平台；**代价**：原生模块，Docker 需 debian-slim 基底而非 alpine |
| 备选驱动 | **`node:sqlite`**（Node 24 起稳定）                                              | 零原生依赖，更符合「一键用」；**代价**：要求 Node ≥24，与当前 `engines: >=22` 冲突             |
| 索引语义 | **纯派生**：启动时校验，缺失或不一致则全量重建；`npm run index` 可手动重建       | 保证红线 R1；任何「只写索引不写 Markdown」的路径都禁止                                         |
| 一致性   | 写 Markdown 成功 → 再更新索引；索引更新失败只降级为「下次重建」，不回滚 Markdown | 单向依赖，避免双写事务                                                                         |

**不引入**：Postgres、Prisma / Drizzle 等 ORM、Redis、向量库（RAG 等有真实需求再说，见第 7 节）。

### 3.3 生成与检索

| 决策       | 选择                                                                          | 理由 / 代价                                                                         |
| ---------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 模型供应商 | **DeepSeek**，走 OpenAI 兼容的 `/chat/completions`                            | 访谈确认；国内可直连、价格低、OpenAI 兼容使换供货商只改配置                         |
| 端点/模型  | `base_url`、`model` 全部走环境变量（默认 `deepseek-chat`）                    | 不把模型名写死；`deepseek-reasoner` 可作「难任务」档位                              |
| 输出约束   | JSON 输出模式 + **zod schema 校验** + **失败重试 1 次**（带错误信息修复提示） | 模型不写文件（红线 R2）：只产出候选 JSON                                            |
| 流式       | **SSE**（`text/event-stream`）按节点增量推送【建议】                          | 生成 30–60 秒必须有进度感；WebSocket 不需要                                         |
| 长任务     | 先同步 + SSE；p95 > 30s 再引入 `jobs` 表 + 轮询【建议】                       | 阶段 5 不做作业队列，避免过早复杂化                                                 |
| 搜索       | **Tavily**（`POST /search`，返回带正文摘要的结果）                            | 访谈指定「用你推荐的」；为 LLM 设计、单 API key、免费额度够个人用（配额以官网为准） |
| 搜索抽象   | `SearchProvider` 接口，Tavily 为首个实现                                      | 便于换 Serper / Brave；也便于测试注入假实现                                         |
| 链接校验   | 只做 `HEAD`/`GET` 可达性与协议白名单（`http(s)`）                             | 不做内容抓取全文，避免 SSRF 与版权问题                                              |

**不引入**：多 provider 路由层、本地模型（Ollama）作为默认路径、爬虫框架。

## 5. 关键契约

### 5.1 模型输出（唯一形态）

模型**只**返回 JSON；结构由 zod 定义，落盘由领域层执行。

```jsonc
// POST /api/generate/map 的模型输出（示意，字段名与现有实体对齐）
{
  "goal_summary": "一句话复述目标，用于自检",
  "nodes": [
    {
      "temp_id": "n1",
      "title": "一元线性回归模型",
      "up": null,
      "order": 1,
      "kind": "枝干",
      "why": "……",
    },
    {
      "temp_id": "n2",
      "title": "总体回归函数与样本回归函数",
      "up": "n1",
      "order": 1,
      "kind": "叶子",
      "why": "……",
    },
  ],
  "materials_seen": ["教材 2.1–2.6 目录"],
}
```

- `temp_id` 只在本次响应内有效；真实 6 位 `id` 由 `vault/ids.ts` 生成，**模型不得指定**。
- `up` 引用 `temp_id` → 落盘时翻译成 `[[{id} {标题}|显示名]]`，标题清洗走现有 `sanitizeFileName`。
- 任何字段缺失/类型错 → 一次修复重试 → 仍失败则**返回 422 + 具体路径**，不写盘。

### 5.2 HTTP 面（阶段 5 起逐步长出来）

| 方法       | 路径                                       | 说明                                       |
| ---------- | ------------------------------------------ | ------------------------------------------ |
| `GET`      | `/api/health`                              | 库状态、索引状态、模型/搜索是否配置        |
| `GET/POST` | `/api/goals`                               | 列出 / 新建目标                            |
| `POST`     | `/api/goals/:id/map`                       | 生成知识网（SSE 流式返回候选，确认后落盘） |
| `POST`     | `/api/goals/:id/path`                      | 生成路径段                                 |
| `POST`     | `/api/goals/:id/resources`                 | 检索候选资源（不自动落盘）                 |
| `POST`     | `/api/assessments` / `/api/retrospectives` | 记录验收 / 复盘                            |
| `POST`     | `/api/export`                              | 导出 Markdown zip                          |

约定：**生成类接口一律「先候选、后写入」两段式**（`preview` → `commit`），提交时带 `expected_revision` 防覆盖。

### 5.3 非功能约束

| 项       | 值                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------- |
| Node     | ≥ 22（ESM，NodeNext 解析，相对导入带 `.js`）                                                   |
| 端口     | `PORT`，默认 3000；默认绑定 `127.0.0.1`                                                        |
| 数据目录 | `SDL_VAULT_PATH` > `.sdlrc.json` > `./vault`；容器内固定 `/data`                               |
| 配置     | 环境变量 + `.env`（`DEEPSEEK_API_KEY`、`TAVILY_API_KEY`、`SDL_LLM_MODEL`、`SDL_ACCESS_TOKEN`） |
| 遥测     | **零**。不向任何第三方上报使用数据；日志只写 stdout                                            |
| 语言     | 界面与生成的实体字段值一律中文（枚举值沿用现有中文枚举）                                       |
| 导出     | 全库随时可导出为纯 Markdown；`.canvas` 仅作可选兼容产物                                        |

## 6. 明确不引入（及其复议触发条件）

| 不引入                       | 复议触发条件                                        |
| ---------------------------- | --------------------------------------------------- |
| SSR 框架（Next / SvelteKit） | 需要 SEO 或首屏 <1s 且 SPA 达不到                   |
| Postgres / ORM               | 需要多用户并发写、或部署形态变成托管服务            |
| Redis / 作业队列             | 生成 p95 > 30s 且需要断点续跑                       |
| 向量库 / RAG                 | 用户开始上传整本 PDF 并要求「按我的材料拆」         |
| Tailwind / CSS-in-JS         | 前端页面数 > 20 且手写 CSS 明显拖慢                 |
| 本地模型默认路径             | 用户明确要求离线生成，且本地模型能稳定产出合规 JSON |

## 7. 技术风险（前三条会直接决定产品成不成立）

1. **结构化输出不稳定。** DeepSeek 在长输出下可能漏字段或破坏 JSON。缓解：分块生成、`json_object` 模式、zod 校验 + 单次修复、失败即 422；**绝不**用正则从自由文本里抠数据。
2. **上下文装不下教材。** 缓解：先索取目录，按小节分块生成，再做「跨块合并 + 同义去重」；合并后**必须重跑覆盖检查**。
3. **费用。** 缓解：单目标默认 token 预算（建议 50k，可配置）、重生成只重跑受影响子图、便宜模型做分类/打标签。
4. **原生模块 + Windows/OneDrive。** 用户库常在中文、带空格的路径下；Docker Desktop 挂载 OneDrive 目录可能极慢或权限异常。缓解：文档给出「库放本地盘、不放 OneDrive」的明确建议；路径处理一律走现有守卫，不手工拼字符串。
5. **索引与 Markdown 漂移。** 缓解：每次写盘递增 `revision`；索引行存 `revision`，不匹配即重建该实体的索引。
6. **公网误暴露。** 缓解：G9 的 fail-closed 规则 + Docker 示例默认 `127.0.0.1:3000:3000`。
