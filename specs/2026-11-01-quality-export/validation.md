## 2. 验收场景

### V1 · 质量面板

1. 选一个有覆盖问题的目标；
2. 面板显示四类分组，其中「地图」组至少一条；
3. `npm run maps` 输出的警告条数与面板一致；
4. 最近失败（若没有，显示「暂无失败」）。

### V2 · 子图重生成

1. 勾选 2 个节点 → 「重生成」；
2. 请求体只有这 2 个 id（可在日志/单测看到）；
3. 返回候选；确认后走 `map/commit` 追加，旧节点仍在；
4. runs 里出现一条成功记录（tokens + 费用）。

### V3 · 预算

1. 目标预算设 1 元；
2. 产生 3 元消耗后，面板 `over: true` 并显示超支；
3. 仍然可以继续生成（不被 4xx/5xx 拦截）。

### V4 · 导出与导入

```bash
curl -s -o export.zip "http://127.0.0.1:3100/api/export"
curl -s -F "file=@export.zip" http://127.0.0.1:3100/api/import
```

1. 空库导入 → `imported` 文件数与源库一致、`skipped` 为空；
2. 再导入一次 → 全部 `skipped`；
3. 目标页/地图/路径能看到导入内容。

### V5 · 安全

构造一个含 `../evil.md` 的 zip → 导入返回 400，库根外没有文件。

### V6 · 真实冒烟（需要 key）

1. 复制真实运行库到临时目录；
2. 导出 → 导入另一个空库；
3. 地图/路径渲染，警告可见；
4. 真 key 重生成 2 个节点，记录 tokens / 费用 / 预算是否超。

## 4. 不通过的样子

- 面板警告数与 `npm run maps` 不一致。
- 重生成偷偷把未勾选的节点也改了。
- 超预算直接阻止生成。
- 费用按字数拍脑袋（与 usage 对不上）。
- 导出把 `.sdl-index.db` 或真实库的 `.obsidian/` 带进去。
- 导入能写到库根之外（zip slip）。
- 导入覆盖了已有文件。
- 真实冒烟写进真实运行库。

## 6. 评审者 5 分钟检查单

1. 面板的四类警告与 `npm run maps` 对得上吗？
2. 勾 2 个节点重生成：请求里只有这 2 个吗？旧节点还在吗？
3. 预算 1 元花了 3 元：是警告还是拦截？
4. 导出的 zip 里有没有 `.sdl-index.db` / `.sdl-runs.json`？
5. 导入两次：第二次是不是全 skipped？
6. 构造 `../evil.md` 的 zip：返回 400 了吗？库外有文件吗？
7. 真实运行库 `git status` 干净吗？
