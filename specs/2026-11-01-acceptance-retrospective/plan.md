## 实施记录（2026-11-01）

T1–T6 完成。用例从 356 增至 **381**。

| 项   | 结果                                                                   |
| ---- | ---------------------------------------------------------------------- |
| 交卷 | `questionIds` 全量补齐；4 题只答 2 题 → **4 条记录**，`unanswered: 2`  |
| 统计 | 正确率分母含未作答、不含复述；按节点聚合                               |
| 建议 | 50% → 在学；0% → 未学；≥80% → 已掌握（单测覆盖 0/79/80/100）           |
| 复盘 | 事件存段 id；`mastery` 经 `createRetrospective` 回写；`order` 前后一致 |
| 页面 | `/assess` 渲染题目与三选一；`/retro` 预填建议、多选段、显示历史复盘    |

实测证据（临时库 `%TEMP%\sdl-assess-demo`，无模型、无 key）：

- 2 个节点、2 段、4 题；
- 交卷：答对 1、答错 1、未作答 2（**4 条记录**，`session sess-j0gx9q`）；
- 建议：最小二乘 50% → 在学；拟合优度 0% → 未学；
- 复盘提交 `mastery: 已掌握` + 两段 → 节点「最小二乘估计」的 `mastery` 变为 **已掌握**；
- 复盘前后 `GET /path` 的 `order`：**1,2 → 1,2**（不变）；
- `/assess` 页面：4 题、12 个单选项、交卷按钮；`/retro` 页面：session、2 段复选、统计「对1 错1 未答2 · 建议在学」、历史复盘 1 条；
- 真实运行库：`git status` 0 个运行库文件被改动。

与计划的偏差：

1. **`adjust_events` 的形态改了**：领域层的 `adjustEvents` 要求**段 id**（会校验存在并转 wikilink），
   所以接口直接收 `stageIds`，页面把 id 映射成「<order>. <title>」；不再存「调整：…」这种字符串。
2. **路由与占位页**：验收/复盘的路由原本指向占位组件 `AssessPage` / `RetroPage`，
   已替换为真正的 `AssessmentsPage` / `RetrospectivesPage`（路径仍是 `/assess`、`/retro`），占位文件删除。
3. **复述可以为空交卷**：只有复述、没有题目时也允许落记录（`questionIds` 为空且无复述才报错），
   否则「复述模式」无法单独使用。

未完成：无。
