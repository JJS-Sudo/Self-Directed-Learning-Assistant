## 2. 验收场景

### V1 · 交卷含未作答

1. 目标下已有 5 道题；
2. 验收页只对 2 题选题答案，其余保持「未作答」；
3. 交卷 → 5 条记录、统计 `correct: 2, unanswered: 3`；
4. `GET /assessments?session=<id>` 返回 5 条。

### V2 · 复述记录

1. 选一个节点，写复述正文，自评「未完成」；
2. 记录里 `mode: 复述`、`result: 未完成`，正文写入受管区块；
3. 统计里 `recitalPending` +1，正确率不变。

### V3 · 复盘回写 mastery

1. 打开复盘页，选本轮 session；
2. 建议值预填（例如 40% → 在学），改选「已掌握」；
3. 提交 → 节点 frontmatter `mastery` 变为「已掌握」；
4. 复盘列表能读到 `worked/failed/next_adjustment`。

### V4 · 调整事件与段序

1. 复盘时多选「第 1 段」「第 3 段」；
2. 生成事件：`调整：「1. …」`、`调整：「3. …」`；
3. 复盘前后 `GET /path` 的 `order` 数组完全一致。

### V5 · 三档边界

| 本轮结果           | 建议   |
| ------------------ | ------ |
| 0 对 0 错 3 未答   | 未学   |
| 3 对 1 错（75%）   | 在学   |
| 4 对 1 未答（80%） | 已掌握 |
| 5 对               | 已掌握 |

### V6 · 全链路（临时库，无模型）

在 `%TEMP%` 的临时库：

1. 路径页落 3 段 6 题（可手写提交，不需要模型）；
2. 验收页交卷（含未作答）→ 统计与建议；
3. 复盘页提交（含段多选与 mastery）→ 事件、掌握度、段序检查；
4. 真实运行库 `git status` 无变化。

## 4. 不通过的样子

- 选 5 题只落 2 条记录（未作答被跳过）。
- 未作答不计入分母，全空交卷却显示 100%。
- 复述被算进正确率。
- 交卷即自动改 mastery，或复盘提交后 mastery 没变。
- `adjust_events` 是空字符串或没有段标题。
- 复盘「调整」顺手改了路径 `order`。
- 复盘页能改题目 / 改段序（超出「记录」范围）。
- 真实冒烟写进真实运行库。

## 6. 评审者 5 分钟检查单

1. 5 题只答 2 题交卷：记录是 5 条吗？`unanswered` 是 3 吗？
2. 0 对 0 错 3 未答：建议是「未学」还是「已掌握」？
3. 复盘提交「已掌握」：节点文件变了吗？
4. 复盘勾了两段：事件里有段标题吗？段序变了吗？
5. 没题目的目标：是 400 还是空表单？
6. 冒烟后：真实运行库干净吗？
