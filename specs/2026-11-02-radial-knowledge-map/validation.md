## 2. 验收场景

### V1 · 形态

1. 复制 `6k74zg`（66 节点）到临时库；
2. 打开 `/map`：目标卡在中心，节点向外发散，边有标签；
3. 截图；记录布局耗时。

### V2 · 四种关系

1. 从 A 拖到 B 选「上级」→ B 的 frontmatter 出现 `links[type=parent]`，且 `upId=B→A`；
2. 从 A 拖到 B 选「并列」→ A/B 中只出现一条 `sibling`；
3. 「相关」同理；
4. 从父拖到子选「下级」→ 实际写在子的 `parent`；
5. 给已有上级的 B 再连一个上级 → 提示「已有一个上级，请用相关」。

### V3 · 编辑

1. 双击卡片改标题 → 文件重命名、`title` 更新；
2. 改序号与掌握度 → frontmatter 变化；
3. 工具栏「加节点」→ 新节点出现、可连线；
4. 点边删除 → 两侧 links 都清理；
5. 删除被路径引用的节点 → 409 列出引用；`force=1` 后删除且路径出现缺失警告。

### V4 · 布局

1. 拖动两个节点 → 刷新页面 → 位置保持；
2. 删除 `知识网/布局.json` → 刷新 → 自动重排；
3. 「刷新布局」按钮 → 清空并重算。

### V5 · 生成

1. 新目标粘贴一段材料 → 生成候选：节点列表 + 边列表；
2. 落盘 → 图上出现「上级 / 并列 / 相关」标签；
3. 故意喂一条引用不存在节点的边 → 丢弃并警告，不写断链。

### V6 · 兼容

1. 打开一个旧目标（frontmatter 只有 `upId`）：正常渲染、能编辑；
2. `npm run maps -- --goal <旧目标>`：canvas 节点数与地图一致。

## 4. 不通过的样子

- 目标不在中心，或仍是上下分栏的树。
- 同一对节点出现两条并列边，或并列只存一边、另一边读不到。
- 「下级」被单独存成一种类型，导致 A→B 与 B→A 各一条。
- 删节点后留下指向它的边（断链）。
- 拖动后刷新回到自动布局，或每次布局位置都不同。
- 生成仍只输出树，图上没有任何类型标签。
- 旧库打不开或必须手工迁移。
- canvas 导出节点数与网页不一致。
- 真实库被冒烟写入。
