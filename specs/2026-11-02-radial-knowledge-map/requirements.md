## 3. 决策

| 编号 | 决策                                                                        | 理由                                      | 影响                                          |
| ---- | --------------------------------------------------------------------------- | ----------------------------------------- | --------------------------------------------- |
| D1   | 关系词表：**上级 / 下级 / 并列 / 相关**                                     | 访谈明确                                  | 存储只留三种机器码，`下级` 由 `上级` 反向推导 |
| D2   | 存储 `parent / sibling / related`，界面按视角显示中文                       | 数据稳定、可迁移；中文只做展示            | 需要在 API/DTO 层映射                         |
| D3   | **上级唯一**（与 `upId` 同步），跨层用「相关」                              | 路径段、覆盖检查、canvas 导出都依赖单父树 | 连第二个上级时提示改用相关                    |
| D4   | 力导向用 `d3-force`；目标节点固定中心                                       | 成熟、可控；中心固定避免整图漂移          | 新增依赖 `d3-force`                           |
| D5   | 布局存 `知识网/布局.json`，不写回节点 frontmatter                           | Markdown 保持干净；布局可删可重建         | 新增文件与读写 API                            |
| D6   | 知识点统一单色，仅目标卡有强调色                                            | 访谈要求「简约风」                        | 卡片样式从类型色改为单色 + 序号 + 掌握度点    |
| D7   | `下级` 只作为**连线时的输入方式**：从父拖到子选「下级」→ 实际写子的「上级」 | 避免同一关系双写、双向渲染混乱            | 渲染时边箭头指向父、标签「上级」              |
| D8   | 生成改造后仍**兼容旧候选**（`parent_temp_id`）                              | 旧库/旧测试不破                           | merge 层同时接受两种输入                      |
| D9   | 删除节点默认级联删边；被路径/题目引用时先警告                               | 防断链，同时不阻断用户                    | 需要引用扫描                                  |
| D10  | canvas 导出继续用现有径向布局                                               | 兼容 Obsidian 用户                        | 本阶段不做 canvas 的带类型边                  |

### 3.1 数据格式

```yaml
# 20-学习项目/<目标>/知识网/n2 最小二乘估计.md
links:
  - to: n1 # 上级
    type: parent
  - to: n5 # 并列
    type: sibling
  - to: n9 # 相关
    type: related
```

- `parent`：最多一条，必须与 `upId` 一致；读取时若只有 `upId` 则自动合成。
- `sibling` / `related`：双向，写入时按 `to` 的 id 字典序规范化去重（只存一条记录，渲染一次）。
- 指向不存在节点的 link：**读取时忽略并提示**，不报错。

### 3.2 API 契约

```ts
// GET /api/goals/:id/map  （扩展）
{
  goal: { id, title, deadline?, daysLeft?, status }
  nodes: { id, title, order, mastery, upId?, links: { to, type }[], relativePath }[]
  layout: { positions: { id, x, y }[] } | null
  warnings: string[]
}

// PATCH /api/nodes/:id          body: { title?, order?, mastery? }
// POST /api/goals/:id/nodes     body: { title, parentNodeId? }            → 新节点（order 自动）
// DELETE /api/nodes/:id?force=1                                            → { deleted, removedLinks, references }
// POST /api/goals/:id/map/links body: { from, to, type: 'parent'|'sibling'|'related' }
// DELETE /api/goals/:id/map/links?from=&to=&type=
// PUT /api/goals/:id/map/layout body: { positions: { id, x, y }[] }

// POST /api/goals/:id/map/preview  body: { material }   → { nodes, edges, warnings }
// POST /api/goals/:id/map/commit   body: { nodes, edges }  → { created, links }
```

- `type` 只收机器码；`下级` 由前端换算成反向的 `parent`；
- 删除被引用节点：`force` 缺省时返回 409 + `references`（路径段/题目），`force=1` 才真正删除；
- 布局坐标必须是有限数字，越界坐标夹到 ±10000。

### 3.3 视觉与交互细节

- 卡片：白底、细边、圆角；左上角序号，右上角掌握度小圆点（未学灰 / 在学黄 / 已掌握绿）；标题最多两行省略。
- 目标卡：深色底、白字，显示标题 + 期限/剩余天数，固定中心，不可删除。
- 边：贝塞尔曲线；`parent` 箭头指向父、标签「上级」；`sibling` / `related` 无箭头、标签「并列」「相关」。
- 工具栏（底部居中）：加节点 / 连线模式 / 适应视图 / 导出 canvas / 刷新布局。
- 右侧详情抽屉：选中节点后显示标题、序号、掌握度、关系列表（可删）、删除节点按钮。
- 连线模式：先点源节点再点目标，弹类型选择（上级/下级/并列/相关），非法组合给提示（第二个上级 → 建议用相关）。

## 5. 风险

| 风险                         | 缓解                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| 力导向抖动/每次位置不同      | 固定随机种子（按节点 id 哈希）+ 首次布局后写文件                     |
| 边标签互相遮挡               | 标签沿曲线中点偏移；可切「隐藏标签」；选中时高亮                     |
| 关系双写导致重复边           | 写入时规范化：`parent` 同步 `upId`；`sibling/related` 去重且只存一条 |
| 删除节点断掉路径/题目        | 先扫描引用，返回 409 并列出，用户确认才删                            |
| 旧数据不兼容                 | 读取时由 `upId` 合成 parent link；旧候选仍可提交                     |
| canvas 导出与网页不一致      | 本阶段 canvas 保持树形径向；文档写明「网页是主视图」                 |
| d3-force 在 SSR/测试里跑不动 | 布局计算包成纯函数 + 固定迭代次数，可在 Node 测试                    |
